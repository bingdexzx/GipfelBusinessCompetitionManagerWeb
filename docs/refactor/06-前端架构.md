> ⚠️ **Windows 专有陷阱（源码内已注明，`vite.config.ts:43-46`）**：`target` 必须写 `127.0.0.1` 而非 `localhost`。
> Windows 上 `localhost` 优先解析到 IPv6 `::1`，而 daphne 默认只监听 IPv4；代理先对 `::1` 建连被 RST 再回退 IPv4，
> 表现为 `vite ws proxy error: read ECONNRESET`，并触发 socket.io 反复重连。跨平台重写请显式绑定 IPv4。

### 4.5 响应拦截器（`request.ts:87-155`）——含**阻塞建包导出**的 blob 缺陷

**成功分支**（`:88-95`）：

```

if (res.code !== 0) → ElMessage.error(res.message || "请求失败") + reject
else return res.data
```

⚠️ **成功判定读 `res.code`，对 blob 响应必然失败**：
`responseType: "blob"` 时 `response.data` 是 `Blob`，`Blob.code === undefined`，
而 `undefined !== 0` 为真 → 直接 `ElMessage.error("请求失败")` + `reject`。
全仓仅两处 blob 请求，恰好是**建包的导出功能**（`api/index.ts:575`、`:587`）：

| 调用方 | 期望 | 实际 |
| --- | --- | --- |
| `PreparationOverviewDialog.vue:416` → `preparationApi.exportFile(...)`（Markdown 报告 / JSON 快照；即建包导出接口的 `format=markdown\|json`） | 拿到 Blob 后 `triggerDownload`（`:398-409`） | 走 `catch`（`:421-427`），弹「导出失败：请求失败」 |
| `PreparationOverviewDialog.vue:435` → `preparationApi.exportArchive(...)`（分组归档） | 同上 | 同上 |

调用方的防御代码（`res instanceof Blob ? res : new Blob([res], …)`，`:417`/`:436`；以及解码 blob 错误的
`blobErrorMessage`，`:385-395`）**在拦截器 reject 之后永远走不到**——即导出功能当前不可用（§17 F-05、U-10）。

**失败分支**（`:96-154`）顺序：

| # | 条件 | 行为 | 行号 |

## 6. 通用 CRUD 组件与数据管理分发

### 6.1 结构：1 个分发器 + 10 个手写管理器 + 1 个不可达的兜底组件

```
路由 meta.type ∈ {maps, parts, products, vehicles, tech-tree, materials,
                  warehouses, production-lines, infrastructures, fuels}
   → DataManagementView.MANAGER_COMPONENTS（10 个 key，与上表完全一致）
   → 对应专用管理器（手写）
否则 → moduleConfigs[type]（空对象）→ DEFAULT_MANAGER = DataManager.vue
```

### 6.2 `DataManager.vue`（480 行）：设计意图 vs 实际状态

**结论：这是一个设计完整但运行时不可达的通用 CRUD 组件。**

| 判据 | 证据 |
| --- | --- |
| 唯一入口是 `DataManagementView.vue:37-39` 的 `DEFAULT_MANAGER` 分支 | 全仓 `DataManager` 字面命中仅 2 处：`DataManagementView.vue:38`（import）与 `MobileCards.vue:44`（注释） |
| 该分支**永不可达**：`managerComponent = MANAGER_COMPONENTS[type] ?? DEFAULT_MANAGER`，而 10 个 key 与 10 条路由的 `meta.type` 完全一致 | `DataManagementView.vue:21-51` vs `router/index.ts:36-143` |
| 它的配置来源是**空对象** | `config/dataModules.ts:27`（文件 27 行）`export const moduleConfigs: Record<string, ModuleConfig> = {}` |
| 因此 `currentConfig` 恒为 `null`，`v-bind="currentConfig"` 分支也不会走 | `DataManagementView.vue:45-47` |

**它的能力合同（若重写要保留这套抽象，以下即需求基线）**：

| 项 | 内容 | 行号 |
| --- | --- | --- |
| props | `title:string`、`columns:Column[]`、`formFields:FormField[]`、`api:{list,create,update,remove,impact?}`、`managePermission?:string` | `:172-185` |
| emits / slots | **都没有**（模板中 0 个 `<slot>`） | — |
| 泛型 | `generic="T extends Record<string, any>"` | `:142` |
| 列定义 | `{prop,label,width?,minWidth?,render?}`；`render` 是组件对象，经 `<component :is>` 注入 `{row,value}` | `:153-159` |
| 表单字段 | `{prop,label,type?,inputType?,min?,multiple?,options?,rules?}`；类型仅 4 种：`text`(默认)/`number`(`BigNumberInput`)/`select`(可多选)/`textarea` | `:161-170` |

**能力边界（撑不住的场景，均有源码证据）**：

| # | 场景 | 证据 |
| --- | --- | --- |
| 1 | **组件当前跑不起来**：`api.list` 类型声明无参（`:177`），调用处传了对象 `(props.api as any).list({ competitionId })`（`:264`）。而现有 `materialsApi.list(page=1, pageSize=50)` 会把**对象当 `page`** 送进 query | `:177` vs `:264` |

### 7.2 `hasPermission` 算法（`catalog.ts:65-86`）

```
role === "SUPER_ADMIN" → 恒 true（短路，:70）
required 可为 string | string[]；数组语义 = 全部满足（AND，:71-72）
对每个 reqKey：
  domain   = key 去掉最后一段（"data:material:edit" → "data:material"）
  reqRank  = 该 domain 等级表中 reqAction 的 rank（未知动作 → 0）
  满足 ⇔ 用户某个权限 p 满足：domainOf(p) === domain 且 rank(actionOf(p)) >= reqRank（:78-82）
空权限数组 → 不满足（fail-closed，:73）
```

**关键性质**：蕴含是**同域**的等级比较，跨域不蕴含。因此 `contract` 域需要单独记忆：
`contract:manage`(40) 蕴含 `contract:audit`(20)、`contract:execute`(30)、`contract:view`(10)；
`contract:execute`(30) 蕴含 `contract:audit`(20) 与 `contract:view`(10)；
而 `contract:audit`(20) 不蕴含 `contract:execute`(30)。
