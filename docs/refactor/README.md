> **这套文档描述的是 git `master` 分支。**
> 工作树可能在 `bugfix-merged` 等分支上、包含 master 没有的功能；**本套文档只以 master 为准**，
> 测量全部针对 `git archive master` 导出的只读目录 `.baseline-master/`。

> 1.98 万行 Python + 2.42 万行 Vue** 就能动手，并知道**哪些东西一动就会出事**。
> **它不是**维护手册，也不依赖任何其它文档——**本套文档自包含**。

## 2. 执行摘要

### 2.1 系统本质

一套**多人在线商业模拟比赛（商赛）的办赛与参赛平台**：主办方建比赛、配产业链、发合同、跑股票市场；
选手在同一场比赛里注册公司、建产线、买卖物料与股票、签约履约；所有客户端通过 WebSocket 实时同步。

**决定一切的四条形态特征**（每条都能在 master 里找到出处）：

| # | 特征 | 证据 |
| --- | --- | --- |
| 1 | **单机、单进程**：HTTP 与 WebSocket 跑在**同一个 daphne 进程** | `backend/asgi.py`、`deploy/gipfel.service` |
| 2 | **实际运行本地 SQLite 文件**（无服务端数据库进程）；但代码里**有 PostgreSQL 双分支**（读 `DB_*` 环境变量），只是**缺 `psycopg2` 驱动** → 目前切不过去 | `settings.py`（`DB_ENGINE` 分支） |
| 3 | **写路径集中化**：任何模型 `save()`/`delete()` 自动产生审计 + 广播 | `apps/common/signals.py` |
| 4 | **实时性是核心体验**：广播带 `seq` 与断线重放 | `apps/realtime/emit.py`、`gateway.py` |

> ⚠️ **并发规模、部署网络形态（是否共用出口 IP）等运行参数，master 中没有记载**。需要时应标【待确认】。

### 2.3 最关键的 10 个事实

| # | 事实 | 为什么关键 | 依据 |
| --- | --- | --- | --- |
| **F1** | **"单进程 + 本地 SQLite"不是一个实现细节，而是整套系统的隐含前提**：广播投递、`seq` 重放环、登录限流计数**全是进程内存状态** | 一旦多进程/多实例，这三样会**同时静默失真**（丢事件、seq 非单调、限流失效） | [00](00-系统全景与运行时.md) §8、[04](04-实时通信协议.md) |
| **F2** | **写路径由模型信号统一驱动**：审计与广播不是视图调用的，而是 `save()`/`delete()` 自动触发 | 这是最优雅也最不可替代的设计；改成"视图里手动广播"**必然漏** | [00](00-系统全景与运行时.md) §5.2/§6 |
| **F3** | **复杂度集中**：`preparation`（4,563 行）+ `stock`（3,776）+ `contracts`（3,755）= **49.5%**；前 6 个 app = **66.3%**；三个巨型单文件是 `contracts/engine.py`（2,723）、`preparation/archive.py`（2,701）、`stock/engine.py`（2,003） | 排期按**文件**估；其余 22 个 app 多为"模型 + 薄视图"，可机械迁移 | [00](00-系统全景与运行时.md) §9 |
| **F4** | **`select_for_update` 在 SQLite 上不是真行锁**；而推进锁是**进程内 `threading.Lock`**（源码 docstring 自述"本锁本身不跨进程"） | 并发正确性目前靠"库级写锁 + 单进程"侥幸成立；换存储或换进程模型都会**改变并发语义** | [05](05-核心引擎与算法.md) §2.1 |
| **F5** | **股票侧数值不可复现**：全仓 `random.seed` **零命中**（`stock` 里 19 处 `random.` 调用） | 验收只能分档：可逐位对拍的量 / 只能统计对拍的量 | [05](05-核心引擎与算法.md) |
| **F6** | **权限键是持久化数据**：39 个键的字面量存在用户表的 JSON 列里 | 改名 = 存量授权全部失效 | [03](03-认证权限与安全.md)、[01](01-领域模型与数据库.md) |
| **F7** | **实时事件名是硬契约**：前端按字符串订阅，服务端按字符串注册 | 改名**不报错、不 401**，只是永不刷新 | [04](04-实时通信协议.md) |
| **F8** | **能力"看起来有、实际不生效"是一个反复出现的模式**：① 有限流中间件与配置端点，但**按角色限流恒放行**（中间件阶段读不到 JWT 用户）；② 有 PostgreSQL 分支与 `DB_*` 变量，但**依赖里没有 `psycopg2`**；③ 有两个互相冲突的 daphne 部署模板（其中一个起 4 个 worker，会切碎单进程内存态） | 重写时**不能按"文件存在"推断"能力可用"**，必须逐条验证生效路径 | [00](00-系统全景与运行时.md)、[02](02-API契约全集.md)、[03](03-认证权限与安全.md)、[04](04-实时通信协议.md)、[07](07-部署运维与环境变量.md) |
| **F9** | **前端存在隐性契约**（见 [06](06-前端架构.md)） | 这类契约在 UI 上"看起来只是排版"，实际是业务语义 | [06](06-前端架构.md) |
| **F10** | **缺少回归网**：`tests/` 下是零散脚本而非测试套件；契约层（HTTP/事件/权限）**没有自动测试** | 重写验收的唯一基线目前不存在 → 必须**先建契约套件** | [08](08-技术债与风险.md) |

## 7. 一分钟版本

> 这是一套**单进程、单机、实际跑本地 SQLite** 的商赛平台：28 个 app、41 个模型、216 个方法级端点、
> 39 个权限键、11 个实时事件。**49.5% 的代码量在三个巨型文件里**
> （`contracts/engine.py` 2,723 行、`preparation/archive.py` 2,701 行、`stock/engine.py` 2,003 行）。
>
> 重写它的难点**不在语言**，而在四件与语言无关的事：
> ① **单进程前提**——广播投递、`seq` 环、限流计数都在一个进程的内存里，多进程即静默失真
>    （而仓库里恰好有一个会起 4 个 worker 的冲突部署模板）；
> ② **并发语义**——`select_for_update` 在 SQLite 分支上不是真行锁，推进锁不跨进程；
> ③ **写路径集中化**——审计与广播由模型信号统一产生，分散到视图必然漏；
> ④ **契约面比 HTTP 宽**——还有权限键字面量（持久化）、枚举字面量、事件名、合同 DSL 的 JSON 形状、前端隐性契约。
>
> 而**最容易踩的一类坑**是「**文件存在 ≠ 能力可用**」：仓库里有按角色限流（恒放行）、
> 有 PostgreSQL 分支（缺驱动）、有建包导出端点（前端必然报错）。
> 这三处本套文档都给了生效路径的逐行举证。
>
> **下一步**：读 [09-重构方案与实施路线.md](09-重构方案与实施路线.md)。
