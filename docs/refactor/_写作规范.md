### 如何复现基准（`.baseline-master/` 是临时产物，交付前已删除）

本套文档中所有 `.baseline-master/xxx.py:NN` 形式的出处，都指向 `origin/master` 的一份只读导出。
**该目录不是仓库的一部分**，读完即弃。要复核任何一条断言，用下面两行重建即可：

```bash
git archive origin/master | tar -x -C .baseline-master     # 需先 mkdir .baseline-master
# 或等价地：git worktree add --detach .baseline-master origin/master
```

> 也可以完全不导出，直接把文中的 `path` 交给 `git show origin/master:<path>` 核对行号。
> **注意**：行号是**在该提交上数的**，与工作树（`bugfix-merged`）普遍不同。

> 🔴 **历史上的两次基准误用（避免重犯）**
> ① 曾以工作树 `bugfix-merged` 为基准 —— 它包含 `master` 没有的 `snapshots` 等；
> ② 曾以**本地 `master` 分支**为基准 —— 它比 `origin/master` **落后 123 个提交**，
>    缺 `preparation`、PostgreSQL 分支、`rate_limit`、`scripts/dev.py` 等。
> **正确基准只有 `origin/master`。** 动笔前先跑 `git fetch && git rev-parse origin/master` 确认。

## 4. 硬性规则（违反即返工）

### R1 · 事实必须可溯源到 `.baseline-master/`
- 写法：`backend/apps/stock/engine.py:120`（**行号必须是在 `origin/master` 上数的**）。
- ⚠️ **行号陷阱**：工作树与 `origin/master` 的行号**普遍不同**（例：`contracts/engine.py` 2,723 行 vs 工作树 2,781 行）。**必须复点行号**，不得沿用旧稿。
- **不确定的标 `【待确认】`** 并写明确认方法。禁止猜测后当事实写。

### R2 · 禁止虚构
- 不发明接口、字段、环境变量、事件名、权限键、命令。
- 数字要么给出获取命令，要么标「约」。
- 计数类结论（model 数、端点数、权限键数…）**必须给出可复现的命令**。

### R3 · 面向重构，不面向维护
- 每章必须有 **「重构关注点」**，分三栏：✅ 必须保持的契约 / 🔄 可自由重设计 / ⚠️ 重构陷阱。
- 鼓励批评设计缺陷——这是本套文档的核心价值。

### R4 · 表格优先
- 清单类内容（字段、接口、权限键、事件、环境变量、缺陷）**一律用表格**。

### R5 · 只写自己那一章
- 写作用域**只有分配给你的文件**。不改源码，**不改其它任何文档**，不改 `docs/` 下既有文件，不改别人的章节。
- 需要别人章的内容 → 写进自己章节的「跨章依赖」小节。

### R6 · 禁止有副作用的命令
- 允许：读 `.baseline-master/`、`grep`、`Select-String`、统计行数、`git cat-file -e origin/master:<path>`。
- 禁止：`migrate`、`makemigrations`、启动服务、`npm install`、改源码、`git commit`/`git checkout`、**任何 `git push`**、写数据库。
- **提交与推送由 Lead 统一执行**，写手一律不得操作 git 写命令。
