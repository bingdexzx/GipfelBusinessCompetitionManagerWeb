### 1.2 `safe_evaluate`：受限表达式求值器

**签名**：`safe_evaluate(expr: str, scope: dict | None = None) -> Any`（`engine.py:956-972`）

| 输入 | 输出/行为 |
| --- | --- |
| `None` 或 `""` | `0`（`:964-965`） |
| `"=a/b"` / `"＝a/b"` | 剥离**一个**前导 `=` / `＝` 后求值（Excel 习惯，`:967-968`） |
| 剥离后为空 | `0` |
| 语法错误 | 抛 `_SafeExpressionError`；`FORMULA` 值源捕获后转 `BusinessError(400)`（`:2011-2016`） |

**词法（`_Tokenizer`，`:606-683`）**

| 记号 | 规则 |
| --- | --- |
| 空白 | `" \t\n\r"` 跳过 |
| 单字符 | `( ) [ ] ,` |
| 数字 | 数字开头，或 `.` 后紧跟数字；支持 `e/E` 指数与符号 |
| 字符串 | `"` 或 `'`；转义 `\n \t \r`，其余 `\X → X` |
| 标识符 | `[A-Za-z_$]` 起，后续 `[A-Za-z0-9_$]` |
| 双字符运算符 | `** == != <= >= && \|\|` |
| 单字符运算符 | `+ - * / % ^ < > !` |
| 其它字符 | **抛错** `不支持的字符: "X"`（`:639`） |

> `_read_number`（`:643-659`）返回元组的第二项是**原文本 `text`**，局部变量 `n` 被丢弃；
> 真正的数字转换在 `_parse_primary`：含 `.`/`e`/`E` 走 `Decimal`，否则走**任意精度 `int`**。
> 非法数字抛 `_SafeExpressionError("非法数字: ...")`（`:658`）。

**优先级（低 → 高）**：`||` → `&&` → `== !=` → `< > <= >=` → `+ -` → `* / %` → `^ **`（**右结合**）→ 一元 `- + !` → 后缀 `[...]` → primary。
对应函数：`_parse_or:819` / `_parse_and:829` / `_parse_equality:837` / `_parse_comparison:846` / `_parse_additive:855` / `_parse_multiplicative:863` / `_parse_power:872` / `_parse_unary:880` / `_parse_postfix:892` / `_parse_primary:901`。

| 运算符 | 语义（**必须逐条复刻**） | 行号 |
| --- | --- | --- |
| `\|\|` | `left if _f_truthy(left) else right`（**无短路**：两侧都已求值） | `:819-827` |
| `&&` | `left if (_f_truthy(left) and _f_truthy(right)) else right` | `:829-835` |
| `==` / `!=` | **`deep_equal`（含 1e-9 容差）**，不是 Python `==` | `:837-844` |
| `< > <= >=` | 先用 `to_number` 转数值再比较 | `:846-853` |
| `+` | `_f_add`：任一侧是 list → 列表拼接；任一侧是 str → **字符串拼接**；否则数值加 | `:708-713` |
| `-` | `_f_sub`：任一侧是 list → 列表差集；否则数值减 | `:716-720` |
| `*` | `to_number(a) * to_number(b)` | `:863-870` |
| `/` | `_f_div`：`y==0 → 0`；`int/int` 整除走 `//`，非整除走 `Decimal(x)/Decimal(y)`（prec 50）；否则 `x/y` | `:723-734` |
| `%` | `0 if b == 0 else to_number(a) % to_number(b)` | `:863-870` |
| `^` `**` | **`math.pow` → 返回 float**（大整数幂丢精度） | `:872-878` |
| 一元 `-` / `+` | `-_f_to_num(v)` / `_f_to_num(v)` | `:880-890` |
| 一元 `!` | `not _f_truthy(v)` | `:880-890` |
| `v[i]` | list：越界或负下标 → `0`；dict：键不存在 → `0`；其它 → `0` | `:737-743` |

**primary（`:901-944`）**

| 输入 | 结果 |
| --- | --- |
| `true` / `false` / `null` | `True` / `False` / `None` |
| `pi` / `e` | `math.pi` / `math.e`（`float`；`_BUILTIN_CONSTS`，`:746`） |
| `name(...)` | `_BUILTIN_FUNCS` → `scope[name]` 可调用对象；都找不到 → 抛 `未知函数`（`:946-953`） |
| `name`（在 scope） | `scope[name]` |
| `name`（未定义） | **`return 0`（静默回退为 0，不报错）**（`:943`） |
| 其它记号 | 抛 `_SafeExpressionError('意外的记号: ...')`（`:944`） |

**内置函数全集（31 个，`engine.py:749-783`）**

| 分类 | 函数 |
| --- | --- |
| 取整/舍入 | `abs` `floor` `ceil` `round` `roundTo(x,n)` `trunc` `sign` |
| 幂/对数 | `sqrt` `cbrt` `pow` `exp` `log(x[,base])` `log2` `log10` |
| 三角 | `sin` `cos` `tan` `asin` `acos` `atan` `atan2` `sinh` `cosh` `tanh` `hypot` |
| 其它 | `mod(a,b)`（b=0 → 0） `clamp(x,lo,hi)` |
| 聚合 | `min` `max` `sum` `avg`（单参数为 list 时展开；空列表 `min/max → 0`、`avg → 0`） |

> `round` / `roundTo` 用 **Python 内置 `round`**（银行家舍入 / half-even），与股票引擎的 `round2`（`ROUND_HALF_UP`）**规则不同**。
>
> ⚠️ `_call_fn`（`:946-953`）只把「未知函数」转成 `_SafeExpressionError`；
> 内置函数的**数学域错误不在此归一**：`sqrt(-1)`、`log(0)`、`asin(2)` 抛原生 `ValueError`，
> `pow(10, 1000)` / `exp(1000)` 抛原生 `OverflowError`。这些异常不是 `_SafeExpressionError`，
> 而 `eval_value_spec` 的 `FORMULA` 分支只捕获 `_SafeExpressionError` → **直接冒到接口层变成 500**。

**`EXPR_HELPERS`（19 个，`engine.py:991-1016`）** —— 与内置函数**不同命名空间**，仅注入 `FORMULA` 沙箱：

| 名称 | 语义 |
| --- | --- |
| `IF(cond,a,b)` | `a if _expr_truthy(cond) else b`（**三参数都会先求值**） |
| `AND(*args)` / `OR(*args)` | 全真 / 任一真 |
| `NOT(x)` | 取反 |
| `len(x)` | list/dict/str 长度；`None → 0`；其它 `len(str(x))` |
| `push(arr,*items)` | 追加 |
| `concat(a,b)` | 拼接为 list |
| `contains(c,x)` | list：元素深相等；dict：先查键再查值 |
| `indexIn(arr,x)` | 首个深相等下标，否则 `-1` |
| `keys` / `values` | dict → list（非 dict → `[]`） |
| `get(o,k)` / `has(o,k)` / `hasKey(o,k)` | `get` 非 dict → `None`；`has` 要求值非 None；`hasKey` 只查键存在 |
| `merge(*objs)` | 浅合并（非 dict 参数被忽略） |
| `unique(arr)` | 保序去重（`deep_equal`） |
| `flatten(x)` | 非 list → `[]`（**丢弃输入**） |
| `join(arr,sep=",")` | 非 list → `str(arr)` |
| `sumOf(arr)` | 非 list → `0` |

> ⚠️ `_expr_truthy`（`:977-988`）与 `is_truthy`（`:213-224`）对字符串**不一致**：
> 前者 `len(v) > 0`（**不 strip**），后者 `v.strip() != ""`。
> `" "` 在 `FORMULA` 的 `IF` 里为真，在效果 `IF` 里为假。

### 1.3 数值归一与相等判定

**`to_number(v, fallback=0)`（`:164-199`）** —— 引擎内部数值 = `int | Decimal`，**绝不产生 float**：

| 输入 | 输出 |
| --- | --- |
| `bool` | `1` / `0` |
| `int` | 原样（任意精度） |
| `Decimal` | 原样；非有限 → `fallback` |
| `float` | `Decimal(repr(v))`；非有限 → `fallback` |
| `None` / `""` / 空白串 | `fallback` |
| 其它 str | 先试 `int(s)`（含大数），失败再 `Decimal(s)`；都失败 → `fallback` |

`decimal.getcontext().prec = 50`（`:39`）**在模块导入时设置全局精度**，影响整个进程的 Decimal 默认行为。
（`company_fields/timer.py:34` 重复设置同一值。）

**`deep_equal`（`:248-297`）** —— **数值比较带 1e-9 容差**：

| 情形 | 规则 |
| --- | --- |
| `a is b` | `True` |
| 任一侧是 `bool` | 仅 `a is b` |
| 两侧都是 `int` | 严格相等 |
| 两侧数值（含 `Decimal`/`float`） | `abs(da - db) < _NUMERIC_EQUALITY_EPSILON`（`1e-9`，`:49`） |
| str ↔ 数值 | 把 str 解析成 `Decimal` 再递归比较（`"200" == 200` 为真） |
| str ↔ str | 严格相等 |
| list | 长度相同 + 逐元素递归（**有序**） |
| dict | 键集合一致 + 逐键递归 |
| 含 `None` | 仅 `None is None` |
| 其它 | `False` |

**`compare_op(actual, op, expected)`（`:313-327`）**：**`EQ` 仅当两侧都是 `int|Decimal` 时用 1e-9 容差**，否则用 `==`；其余比较符原生比较；`default` 落到 `GTE`。

#### 1.8.1 字段效果的三元语义（`apply_field_effect`，`:382-486`）

输入：`current_raw`（存储字符串）、`field_type`、`config`、`op`、`new_value`；输出 `{store, before, after}`。

| 字段类型 | `ADD` | `SUB` | `SET` |
| --- | --- | --- | --- |
| `NUMBER` | `before + value` | `before - value` | `value` |
| `STRING` / `BOOLEAN` | **`cast_scalar` 覆盖（op 被忽略）** | 同左 | 同左 |
| `LIST` | 追加 + 按 `deep_equal` 去重 | 按元素移除 | 整体替换 |
| `DICTIONARY` | `value` 是 dict → 共有键**数值相加**、独有键保留；是 str → `{value: True}` 后合并；其它 → 合并空 dict（**无操作**） | `value` 是 **list** → **删键**；是 **dict** → 逐键数值相减（**保留键**）；是标量 → 删该键 | 整体替换 |

- LIST 的 `item_type = config.itemType or config.valueType or "STRING"`；DICT 的 `value_type = config.valueType or "STRING"`；每项都过 `cast_scalar`。
- `before` 的解析：LIST/DICT 先尝试 `json.loads` 字符串；NUMBER 走 `parse_stored_field_value`（`:344-365`，空串 → `None` → `to_number(None) = 0`）。
- **⚠️ NUMBER 的 float 化（`:482-486`）**：算完后若 `after` 是 `Decimal` 且**非整数**，会被转成 `float`。
  这与「引擎内部绝不产生 float」的承诺（`:35-38`）矛盾——`10^23` 量级**带小数**的金额会退化为 double。整数 `Decimal` 走 `int()`（无损）。
- `store = dumps_engine_json(after)`（`:72-89`）：整数 `Decimal → int`（JSON number）；非整数 `Decimal → 定点字符串`（`format(o,"f")`）。**float 走 JSON number**。

`combine_values(v1, v2, vop, field_type)`（`:560-583`）：`value2` 存在时先算 `value ⟨valueOp⟩ value2`——
LIST/SUB → 差集；DICT/SUB → 按**键**求差；`STRING` → **返回 `v1`（忽略 v2）**；`BOOLEAN` → `v1 is True or "true" or 1 or "1"`；数值默认 `ADD`。

### 1.11 `revert_contract`：事件溯源重放

**前置条件**：必须在合同行被删除**之前**调用（`ContractFieldEffect` 是 CASCADE）（`:2194-2198`）。

算法（`:2203-2264`）：

```
1. 读本合同全部 ContractFieldEffect（id, company_id, industry_field_id, field_key,
   op, value_raw, before_raw）→ 空则直接 return
2. 去重受影响字段对 (company_id, industry_field_id)
3. 读这些字段的 IndustryField（field_type / config / default_value）
4. 读「其余已执行合同」对这些字段的增量，按 (contract.executed_at, id) 升序
5. 逐受影响字段：

#### 事务与锁（**本章头号时序风险**）

| 机制 | 实现 | 真实效果 |
| --- | --- | --- |
| 进程内锁 | `_advance_locks: dict[int, threading.Lock]` + `_try_acquire_advance_lock`（`:1842-1859`） | 单进程有效；**不跨进程**（注释 `:1850-1852` 自己承认） |
| 行级锁 | `if connection.vendor != "sqlite": qs = qs.select_for_update()`（**`:1928-1929`**） | **SQLite 上完全不执行，即 no-op**（注释 `:1923` 自认） |
| 整轮事务 | `with transaction.atomic()`（`:1924`） | 全部股票要么全成要么全回滚 |
| 信号抑制 | `with suppress_signals()`（`:1951`） | 循环内 `save()` 不逐条广播/审计；循环后统一 bulk 广播 + 审计 |

> **`select_for_update` 在 SQLite 上的实际行为**：项目使用 `django.db.backends.sqlite3`，
> 而代码显式判断 `connection.vendor != "sqlite"` → 该行锁**永不生效**。
> 当前串行性只来自 ① SQLite 的库级写锁；② 进程内 `threading.Lock`。
> **一旦换用非 SQLite 后端**（行锁真正生效的数据库）：`select_for_update` 变成真行锁，`Stock` 行被 `FOR UPDATE` 持有到事务结束；
> 而事务内还要写 `StockOrder` / `StockHolding` / `StockFundsAccount` / `StockCandle` / `CompanyFieldValue`
> → 跨比赛共享账户/公司时会出现**行锁等待 → 潜在死锁**（加锁顺序不一致：`Stock` 按 `code` 排序加锁，
> 账户/持仓按撮合顺序加锁）。**重写时必须显式定义互斥范围，不得依赖库锁侥幸串行。**

> ⚠️ **`_release_advance_lock` 存在冗余的第二次 `release()`（`:1862-1874`）**：函数体连调两次 `lock.release()`（`:1868`、`:1872`），两次的 `RuntimeError` 都被吞掉。
> **但「它会释放他人持有的锁」这一推断不成立**，三条反证（均可在 master 上逐行核对）：
> ① **非持有者到不了这里**——`advance_round` 在 `_try_acquire_advance_lock` 失败时于 `:1899` 直接 `raise`，
>    而该 `raise` 位于 `try`（`:1902`）**之前**，因此对应的 `finally`（`:2002-2003`，也是全文件唯一的 `_release_advance_lock` 调用点）不会执行；
> ② **两次 release 之间插不进 acquire**——`_release_advance_lock` 在 `:1864` 起的**整个 `with _advance_locks_guard` 块内**完成两次 release，
>    而 `_try_acquire_advance_lock` 也必须先获取**同一把非重入的** `_advance_locks_guard`（`:1843`、`:1854`），
>    故第二次 release 必然打在已解锁的锁上 → `RuntimeError` → 被吞 → **当前无害**；
> ③ **真正的并发风险源码自己写明了**——`:1852` 的 docstring 原文：「**本锁本身不跨进程**」。
>    即：单进程部署下它有效；**一旦多进程/多 worker，各进程各持一把独立锁 → 同一比赛可被并发推进。**
>
> **重写结论（据此修正）**：要修的不是那个冗余 release，而是**跨进程互斥本身**。
> 该冗余 release 只应被理解为「这把锁既不校验持有者、也不跨进程」的**征兆**。
> 同一文件还有 `_advance_locks` 只增不减的内存泄漏（`:1843`）。

### 2.2 撮合算法（完整还原）

**三阶段**：① 全局预检（`compute_match`）→ ② 逐笔价格-时间优先（`advance_one_stock` 内联循环）→ ③ 结算与订单状态。

#### 阶段 1：全局预检（`compute_match`，`:89-124`）

```
输入 orders: [{side:"BUY"|"SELL", price, quantity}, ...]
buys  = [o for o in orders if o["side"] == "BUY"]
sells = [o for o in orders if o["side"] == "SELL"]
highest_buy  = max(o["price"] for o in buys,  default=0)      # 空集合 → 0
lowest_sell  = min(o["price"] for o in sells, default=0)      # 空集合 → 0
total_buy_qty  = Σ o["quantity"] (buys)
total_sell_qty = Σ o["quantity"] (sells)
total_buy_amount  = Σ o["price"] * o["quantity"] (buys)
total_sell_amount = Σ o["price"] * o["quantity"] (sells)
matched = len(buys) > 0 and len(sells) > 0 and highest_buy >= lowest_sell
tradePrice = (highest_buy + lowest_sell) / 2 if matched else None
```

> `tradePrice` 是**参考价**（最高买与最低卖的中点），**不是**实际成交价。实际成交价见阶段 2 的「夹价」。

#### 阶段 2：逐笔撮合（`engine.py:1622-1700`）

```
buys  = sorted([BUY 单], key=lambda o: (-o.price, o.created_at))   # :1623-1626 价格降序，同价 FIFO
sells = sorted([SELL单], key=lambda o: ( o.price, o.created_at))   # :1627-1630 价格升序，同价 FIFO
buy_rem[id]  = Decimal(o.quantity);  sell_rem[id] = Decimal(o.quantity)
filled       = {}
trade_price  = Decimal(str(match["tradePrice"])) if match.get("tradePrice") is not None else None
cash_map     = {账户id: 可用现金(Decimal)}       # :1599-1611 绑字段账户取字段值，否则取 account.cash_balance
holding_map  = {账户id: {"shares": Decimal, "costPrice": Decimal}}   # :1614-1619，只查下单账户
trade_prices = []

bi = si = 0
while bi < len(buys) and si < len(sells):
    buy, sell = buys[bi], sells[si]
    if buy.price < sell.price: break                       # 不再交叉 → 结束
    qty = min(buy_rem[buy.id], sell_rem[sell.id])

    # ① 夹价：全市场统一价可能越出某笔委托的限价
    pair_price = min(max(trade_price, Decimal(str(sell.price))),
                     Decimal(str(buy.price)))              # :1649-1652，∈ [sell.price, buy.price]

    # ② 买方现金约束
    buy_cash = cash_map[buy.funds_account_id]
    if qty * pair_price > buy_cash + EPS:                  # EPS = Decimal("1e-9")，:39
        qty = buy_cash / pair_price
        if qty <= EPS: buy_rem[buy.id] = Decimal("0"); bi += 1; continue

    # ③ 卖方持仓约束
    sell_shares = holding_map[sell.funds_account_id]["shares"] if 存在 else Decimal("0")
    if qty > sell_shares + EPS:
        qty = sell_shares
        if qty <= EPS: sell_rem[sell.id] = Decimal("0"); si += 1; continue

    # ④ 6 位小数量化（★ 量化后没有任何归零保护，见下方陷阱）
    qty = (qty * Decimal("1000000")).quantize(Decimal("1"), rounding=ROUND_HALF_UP) / Decimal("1000000")
    trade_prices.append(pair_price)

    # ⑤ 结算（内存）
    cash_map[buy]  -= qty * pair_price
    new_shares = bh.shares + qty
    new_cost   = (bh.shares*bh.costPrice + qty*pair_price)/new_shares if new_shares > 0 else pair_price
    cash_map[sell] += qty * pair_price
    shares[sell]    = max(Decimal("0"), shares[sell] - qty)   # 成本价不变
    filled[buy] += qty;  filled[sell] += qty
    buy_rem[buy.id]  -= qty;  sell_rem[sell.id] -= qty
    if buy_rem[buy.id]  <= EPS: bi += 1
    if sell_rem[sell.id] <= EPS: si += 1
```

**输出**：`filled[]`、`cash_map` / `holding_map`（内存终值）、`trade_prices[]`。

| 边界 | 行为 |
| --- | --- |
| 空订单（无任何 PENDING） | `advance_one_stock` 提前走**平盘推进**（`:1424-1445`），不进撮合 |
| 单边无对手盘 / 价格不交叉 | `matched=False` → **丢弃 `price["final"]`**，走平盘推进（`:1570-1580`） |
| 判定可成交但现金/持仓把成交量夹到 0 | 撮合循环内 `continue`，`trade_prices` 为空 → `build_candle(trade_high=None, trade_low=None)` |
| 委托全量成交 | `remaining <= EPS` → `status="FILLED"` |
| 部分成交 | `quantity=round2(remaining)`、`amount=round2(price*remaining)`，**状态仍 PENDING** |

> ⚠️ **量化归零可致无限循环（`:1668-1700`）**：`if qty <= EPS` 的保护只存在于现金/持仓夹紧分支（`:1656-1659, :1664-1667`），
> **量化之后没有任何归零检查**。若现金或持仓夹紧后的 `qty ∈ (1e-9, 5e-7]`，
> 则 `(qty * 1e6).quantize(1, ROUND_HALF_UP)` → `0`；随后 `buy_rem -= 0`、`sell_rem -= 0` 均不变，
> `buy_rem <= EPS` 与 `sell_rem <= EPS` 都为假 → **`bi`/`si` 都不推进，外层 `while` 永久停在同一对委托上**。
> 触发条件可构造成「买方可用现金为亚分级残值」或「卖方持仓为亚分级残值」。确认方法见 §11.2 的 U-02。

### 2.3 定价（纯函数）

| 步骤 | 公式 | 行号 |
| --- | --- | --- |
| 净买压力 | `pressure = (buyQty - sellQty) / (buyQty + sellQty + 1)`（分母 +1 防除零，值域 (-1,1)） | `compute_pressure:128-131` |
| 碳排偏置 | `avg <= 0 → 0`；`carbon <= 0 → 1`；否则 `min(1, -ln(r)/k)`，`r = carbon/avg`，`k = ln(saturate_ratio if >1 else 2)` | `:134-150` |
| 趋势偏置 | `h = (happiness - 50)/50`；`drift = happinessImpact*h + carbonImpact*carbonDrift` | `:153-164` |
| 理论价 | `theoretical = lastClose * (1 + pressure*maxMovePct + drift*maxMovePct)` | `:167-174` |
| 最终价 | 见下 | `compute_price:177-222` |

```
compute_price(factors, config):
    upper_pct = config.get("upperLimitPct", config["limitPct"])
    lower_pct = config.get("lowerLimitPct", config["limitPct"])
    upper = lastClose * (1 + upper_pct);  lower = lastClose * (1 - lower_pct)
    if matched and tradePrice is not None and isfinite(tradePrice):
        w = config["tradePriceWeight"]                       # 默认 0.7
        blended = w*tradePrice + (1-w)*theoretical
        final = clamp(blended, lower, upper)                 # float 运算
        usedTradePrice = True
    else:
        final = clamp(lastClose, lower, upper)               # 未成交 → 不动（但调用方会丢弃）
        usedTradePrice = False
    final = round2(final)                                    # Decimal, 2 位, ROUND_HALF_UP

```

> 价格**由 `_advance_round_flat` 的趋势漂移重新决定**（见 §2.10）。
> `pressure`/`drift`/`theoretical` 仍作为**诊断值**返回给调用方。

### 2.4 市场自然波动与回调（`advance_one_stock:1493-1563`）

在 `compute_price` 之后、最终限幅之前，若 `mmCallbackEnabled`（默认 `True`）：

```

if recent_candles:
    recent_changes = 最近 5 根的 change_pct；avg_change = mean(recent_changes)

        final_price *= (1 + Decimal(str(sentiment * pct)))

upper_bound = last_close * (1 + cfg.upperLimitPct)    # :1561-1563 非对称限幅，防连板生效点

⚠️ 这里的 `candle_consec_up/down` 阈值是 `> 0` / `< 0`，**与防连板用的 `≥ 9.9` 口径完全不同**——两套「连续」定义并存。
注释 `:1560` 自述这是「P0-#5：市场波动后强制限制在涨跌停范围内（防止防连板被绕过）」——即**撮合路径的防连板不可被这段随机波动绕过**。

### 2.5 K 线生成（`build_candle`，`:225-322`）

```
输入: open_, close, round_, theoretical=None, limit_pct=0.1,
      upper_pct=None, lower_pct=None, trade_high=None, trade_low=None

open_ = float(open_); close = float(close)          # :245-247 入口统一转 float（避免 Decimal 混算）
up_pct = upper_pct if not None else limit_pct
dn_pct = lower_pct if not None else limit_pct
upper = float(round2(Decimal(str(open_)) * (Decimal("1") + Decimal(str(up_pct)))))
lower = float(round2(Decimal(str(open_)) * (Decimal("1") - Decimal(str(dn_pct)))))
range_ = upper - lower

body_high = float(max(open_, close));  body_low = float(min(open_, close))
high, low = body_high, body_low
if theoretical is not None and isfinite:  t = clamp(theoretical, lower, upper); high=max(high,t); low=min(low,t)
if trade_high is not None and isfinite:   high = max(high, clamp(trade_high, lower, upper))
if trade_low  is not None and isfinite:   low  = min(low,  clamp(trade_low,  lower, upper))

price = float(open_)
if price > 0:
    if trade_high is not None and trade_low is not None:
        base_wick = float(trade_high - trade_low) * (0.3 + 0.4*candle_noise(round_, open_))
    elif theoretical is not None and isfinite:
        base_wick = abs(float(theoretical) - close) * (0.5 + 0.5*candle_noise(round_, open_))
    else:
        change_pct_abs = abs(close - open_) / price if price > 0 else 0
        base_wick = price * (0.003 + min(0.007, change_pct_abs*0.3))
    up_wick   = base_wick * (0.6 + 0.8*candle_noise(round_, open_))
    down_wick = base_wick * (0.6 + 0.8*candle_noise(round_*3 + 7, open_))
else:
    wick = range_ * 0.05
    up_wick   = wick * candle_noise(round_, open_)
    down_wick = wick * candle_noise(round_*3 + 7, open_)

high = float(round2(min(upper, high + up_wick)))
low  = float(round2(max(lower, low  - down_wick)))
change_pct = float((Decimal(str(close - open_)) / Decimal(str(open_)) * 100)
                   .quantize(Decimal("0.01"), ROUND_HALF_UP)) if open_ != 0 else 0
return {round, open, high, low, close, changePct}
```

**确定性伪随机**：`candle_noise(a, b) = frac(sin(float(a)*127.1 + float(b)*311.7) * 43758.5453)`（`:79-85`）。
完全由 `(round_, open_)` 决定——同样的轮次与开盘价必然得到同样的影线。

> **入口的 `float()` 归一（`:245-247`）是必须复刻的**：否则 `Decimal / float` 会抛
> `TypeError: unsupported operand type(s) for /: 'decimal.Decimal' and 'float'`，
> 而 `_advance_round_flat` 与成交路径都会把 `Decimal`（`Stock.current_price`、`round2` 的 `final`）传进来。
> 注释 `:255` 亦明确「body_high/low 可能是 Decimal（来自 ORM/price["final"]），统一转 float 后再计算」。

### 2.7 防连板机制（S10）

**常量**（`:377-383`）：

```python
_ANTI_STREAK_FACTOR  = 0.96     # 同侧限幅收缩系数（注释 :377-378 同口径）
_ANTI_STREAK_CAP_PCT = 0.096    # 同侧限幅绝对上限 9.6%
```

**生效位置**（`advance_one_stock:1463-1474`）：

```python
limit_pct = stock_config["limitPct"]

```

**封板判定**（`advance_round:1955-1965`）：上一根 K 线 `change_pct >= 9.9` 记 up，`<= -9.9` 记 down，否则 `break`（只看最近 3 根）。

| 场景 | 是否受防连板约束 |
| --- | --- |
| `matched=True` 的正常撮合路径 | ✅ 限幅经 `cfg.upperLimitPct/lowerLimitPct` 收紧到 ≤9.6%，且随机波动后**再次**夹紧（`:1561-1563`） |
| 无任何订单 / `matched=False` | ❌ 走 `_advance_round_flat`，用**未收紧**的 `limit_pct`（见下） |
| K 线上/下影线 | 撮合路径传收紧后的 `upper_pct/lower_pct`（`:1702-1707`）；平盘路径传 `limit_pct`（`:1271-1273`） |

> ⚠️ **防连板可被「平盘轮」绕过**（`_advance_round_flat:1243-1266`）：
> ```
> trend_drift    = drift * (1 + uniform(-0.6, 0.6))
> base_noise_pct = uniform(-0.02, 0.02)
> theoretical    = old_price * (1 + trend_drift*maxMovePct + base_noise_pct)
> upper = old_price*(1+limit_pct); lower = old_price*(1-limit_pct)
> new_price = round2(clamp(theoretical, lower, upper))      # ← 用未收紧的 limit_pct
> ```
> 涨跌幅上界 = `drift*1.6*maxMovePct + 0.02`。以基准的默认参数（`happinessImpact=carbonImpact=0.3`、`maxMovePct=0.08`）计算，
> 需 **`drift ≥ 0.617`** 才能触到 10% 限幅；而 `drift = 0.3*h + 0.3*c`，`c` 在零/负碳排时为 1，
> 于是 **`happiness ≥ 约 103`** 即可能打出 10.00% 的平盘 K 线 → `change_pct = 10 ≥ 9.9` → **被判定为封板**。
> 即「连续封板在数学上不可能」这一不变式**只在撮合路径成立**。确认方法见 §11.2 的 U-03。

> ⚠️ **注释与代码不一致（重写时以代码为准）**：
> | 位置 | 注释说 | 代码是 |
> | --- | --- | --- |
> | `stock/engine.py:1463-1466` | 「收紧（**94% 且不超过 9.4%**）」「单轮最大变动 < 9.9%」 | `0.96` / `0.096`（`:379, :383`） |
> | `stock/engine.py:1453` | 「防连板硬约束会把同侧限幅收紧到 **9.4%**」 | 同上 |
> | `stock/engine.py:377-378` | 「收紧到 **96%**」「10% × 0.96 = **9.6%** < 9.9%」 | ✅ 与代码一致 |
> 常量区的注释是对的，**使用点的两处注释是旧值**。

**其他机制**

| 机制 | 参数 | 触发 | 位置 |
| --- | --- | --- | --- |
| `interventionMode = "regression"` | 连续封板 ≥3 轮 | 挂反向大单（量 = `base_quantity * 2 * min(consec,2) * mm_intensity`） | `:1026-1033`, `:1079-1104` |

> ⚠️ **三重舍入精度冲突**（重写必须选一个口径）：
> 1. 撮合数量量化到 **6 位小数**（`:1669`）；
> 2. 持仓/现金/剩余委托**入库前 `round2` 到 2 位小数**（`:1716-1722`, `:1770-1782`）；
> 3. 模型列声明 `decimal_places=4`（`stock/models.py`）。

> 表现为「账户股数与成交记录对不上」。

> ⚠️ **`effective_industry_avg_carbon` 用 `round()` 而非 `round2`**（`:538`）：

### 3.4 依赖排序与环检测

**`_order_calc_fields`（`calc.py:165-193`）—— 拓扑排序（DFS 后序）**

```
calc_keys = {field_key: field}
deps[key] = (_graph_field_refs(field.calc_graph) & set(calc_keys)) - {key}       # 只保留计算字段间依赖
visit(key, field):
    if key in done: return
    if key in visiting: warn("依赖成环，按定义顺序兜底"); return
    visiting.add(key)
    for dep in sorted(deps.get(key, ())):
        if dep in calc_keys: visit(dep, calc_keys[dep])
    visiting.discard(key)
    if key not in done: ordered.append(field); done.add(key)
for f in calc_fields: visit(f.field_key, f)
```

环检测**非严格**：发现环只 warn 并按原顺序兜底，不阻止重算。

**`_graph_field_refs`（`calc.py:139-162`）—— 引用提取（启发式）**

1. `kind == "FIELD"` 节点 → `d["fieldKey"]`（`:158`）；
2. `kind == "FORMULA"` 节点 → `_formula_field_refs(expr, known_keys)`（`:160` → `:106-136`）：
   先剔除 `"..."`、`'...'`、`` `...` `` 字符串字面量，再扫描标识符 `[A-Za-z_][A-Za-z0-9_]*`；
   - 排除 `_FORMULA_RESERVED`（mathjs 关键字，`:94-100`，**刻意不含 `e`/`pi`/`phi`**）；
   - 仅当后面紧跟 `(` 时排除 `EXPR_HELPERS` 名（函数调用形态）；
   - `known_keys` 非空时只保留确属本产业类型的字段键（过滤 assign 局部变量）。

**定义侧环检测（`industry_types/views.py:194-265`）** —— 与求值侧不同，这是**严格拦截**：
DFS 三色标记（`WHITE/GRAY/BLACK`），成环 → 返回节点序列（如 `[a, b, a]`）→ 视图抛 `BusinessError`。
创建（`:498-507`）与更新（`:598-612`）两条路径都调用；改名时通过 `renamed_from` 预演改名后的引用关系（`:229-231`）。

> ⚠️ **两套环检测口径不同**：定义侧「成环即拒绝写入」，求值侧「成环则 warn + 兜底」。
> 存量数据可能绕过定义侧，所以求值侧兜底仍然必需。

### 3.5 级联重算 `recompute_calc_fields(company_id)`（`:400-469`）

```

**`_trim_number_trailing_zeros`（`:385-397`）**：`'1.0'→'1'`、`'1.50'→'1.5'`、`'0.0'→'0'`、`'-1.50'→'-1.5'`；

| 实现 | 位置 | 冲突行为 |

### 7.1 Dijkstra（`contracts/engine.py:1762-1817`）

```
_dijkstra(adj, start, goal):                     # :1762
    if start == goal: return 0
    dist={start:0}; visited=set(); pq=[(0,start)]
    while pq:
        d,u = heappop(pq)
        if u == goal: return d
        if u in visited: continue
        visited.add(u)
        for to,w in adj.get(u,[]):
            nd = d+w
            if nd < dist.get(to, inf): dist[to]=nd; heappush(pq,(nd,to))
    return inf                      # 不可达

_dijkstra_path(adj, start, goal):                # :1783
    同上，但 goal 弹出后 break + 前驱回溯；不可达 → (inf, [])
    adj 值元组为 (邻居, 权重[, ...])，前两元素参与计算，余项忽略
```

- 邻接表**双向**构建（每条边两个方向，同权重）→ 视为无向图。
- 权重 `to_number(distance)` → `int`/`Decimal`；堆节点 `(distance, node_id)`，**node_id 参与比较**（同距离时按 id 排序，稳定）。
- `compute_route_distance`（`:1627`）对**每一段**跑一次 Dijkstra；不可达 → `BusinessError(400)`。
- `compute_route_path_types`（`:1652`）不可达时**跳过该段**（不报错）。
- `EvalCtx.cache`（`:1259-1273`）按 `competition_id` 缓存邻接表；**`compute_route_path_types` 不传缓存**，每次重建。

### 7.2 写信号抑制器（E9，`common/signals.py`）

`suppress_signals`（`:39-59`）是 **thread-local 开关**：`__enter__` 保存旧值并置 `False`，`__exit__` 还原。
所有 `post_save` / `post_delete` 处理器入口先查 `_is_enabled()`（`:94, 137`），关闭时**跳过审计与广播**。

`connect_all_signals`（`:177-203`）在 `CommonConfig.ready()` 对**有 `MODEL_TO_RESOURCE` 映射且映射值非 None** 的模型统一 connect。
`_on_post_save` 仅在 `isinstance(instance.pk, int)` 时广播（`:107-109`）。

### 8.3 导入算法（`apply_import`，`archive.py:2589-2699`）

```
1. ctx = ImportContext(cid, dry_run, allow_non_empty, mode, only_resources, user)     # :433-535
2. 目标比赛存在性检查 → 不存在抛 ArchiveError("目标比赛不存在")                        # :2627-2628
3. occupancy = competition_occupancy(cid)                                            # :2573
   if occupancy and not allow_non_empty:
       dry_run → ctx.problem(msg) 并返回 blocked=True 的预览（不抛错）                 # :2638-2652
       否则    → raise ArchiveError                                                   # :2653
4. 预扫 companies 行 → ctx.old_company_names（供账号按公司名兜底映射）                  # :2656-2658
5. ordered = [r for r in IMPORT_ORDER if r in resources and ctx.wants(r)]              # :2661
   skipped_resources = [r for r in IMPORT_ORDER if r in resources and not ctx.wants(r)]
6. with transaction.atomic():                                                          # :2666  ← 唯一事务
       for res in ordered:
           rows = resources[res]["rows"]；空 → continue
           fn = _IMPORTERS.get(res)                                                    # :2485
           fn is None → problem + continue
           rows = _filter_rows_for_mode(res, rows, ctx)     # :1555，追加模式跳过「父已保留」的子行
           空 → continue

           except Exception as e:                                                      # :2681-2683
               ctx.problem(f"资源 {X} 导入失败：{类型}: {e}"); ctx.bump(res, "skipped", len(rows))
       if dry_run: transaction.set_rollback(True)                                      # :2684-2685
7. 组装 result：created/updated/skipped/kept、resources 明细、problems、notes、mode、modeLabel、

   problemCount、noteCount
```

**事务策略（docstring 与代码的差异，重写时以代码为准）**

| 说法 | 代码事实 |
| --- | --- |
| docstring 称「`dry_run=False`：整体成功才提交；出现异常则回滚并抛出」（`:2608-2610`） | 代码是**单个外层 `transaction.atomic()`**，每个资源只有 `try/except`（`:2679-2683`），**没有 per-resource savepoint** |
| 后果 | 一次**数据库**错误（IntegrityError / 约束冲突）会把整个外层事务标记为「需回滚」；后续资源的 ORM 查询会抛 `TransactionManagementError`，被同一个 `except` 吞成 problem；退出 `atomic` 时整批数据回滚，但接口返回的 `created/updated` 统计**在失败前已经加过** |
| `dry_run=True` | `set_rollback(True)` → 不留任何数据（`:2684-2685`） |

**非空保护探针（`competition_occupancy`，`:2573-2586`）**

## 10. 可复现性与验收分档

**前提**：全仓 **`random.seed` 命中 0**（§0.4 命令）。因此「结果等价」在股票侧**不能**表述为「逐位相等」。

### 10.1 ✅ A 级：可以逐位对拍（确定性，必须 `==` 相等）

| 量 | 为什么确定 |
| --- | --- |
| **撮合配对结果**（哪些买单与哪些卖单成交、各成交多少股） | 排序键 `(-price, created_at)` / `(price, created_at)` 完全确定；夹价、现金/持仓夹紧、6 位量化都是纯算术 |
| **`pair_price` 与 `trade_prices[]`** | `min(max(trade_price, sell.price), buy.price)`，`trade_price = (highest_buy + lowest_sell)/2` |
| **成交后的现金/持仓增量** | `qty * pair_price` 的 Decimal 算术 + `round2` |
| **K 线 OHLC 与 `changePct`** | `build_candle` 内部**无 `random`**（影线由 `candle_noise` 决定） |
| **`candle_noise` 的影线长度** | 正弦哈希；`math.sin` 在**同一平台**上确定（跨平台见 U-04） |
| **`pressure` / `carbon_drift` / `theoretical`** | 纯函数 |
| **`compute_init_price`** | 纯 Decimal 算术 |
| **合同引擎全部结果**（条件判定、字段效果、聚合、公式） | 引擎内**不使用 `random`** |
| **计算图求值结果** | 同上 |
| **`revert_contract` 的重放结果** | 纯确定性（缺陷见 T9） |
| **财年定时器写入值** | 纯确定性 |
| **归档导出结果**（同库状态下） | 纯查询 + 确定性序列化；`RefResolver` 的按名兜底只在导入侧 |
| **体检报告的统计与状态判定** | 纯查询 + 确定性规则（`_status_of`） |
| **`resources_of_scope` / `scope_options` 的顺序与内容** | 纯常量 + `IMPORT_ORDER` 排序 |

### 10.2 📊 C 级：只能做统计对拍（分布等价 + 边界等价）

| 量 | 随机来源 | 可对拍的性质 |
| --- | --- | --- |
| **做市商报价参数**（`spread_pct` / `levels` / `skew_pct` / `depth_pct` / `base_quantity`） | `add_fluctuation`（`:71-76`） | clamp 边界（`base*0.7 ~ base*1.3`）、`levels ∈ [1,10]`、单调关系 |
| **做市商新闻冲击** | `mmBadNewsProb` / `mmGoodNewsProb` 两次独立 `random.random()`（`:1000-1009`） | 触发频率期望、幅度区间 `[impact*0.3, impact*1.2]` |
| **自成交方向与价格偏移** | `random.random() < 0.7` / `random.choice`（`:1156-1170`） | 方向概率 70/30、`abs(last_change)` 阈值边界 |
| **PE 随机游走** | `random_pb` / `random.random()*4-2`（`:545, :646`） | `clamp_pb` 的 `[0,20]` 边界、步长 ∈ [-2,2] |
| **平盘趋势漂移与基础噪声** | `uniform(-0.6,0.6)` / `uniform(-0.02,0.02)`（`:1254, :1257`） | 幅度上界、限幅边界 |
| **市场情绪 / 技术性回调** | `random.random/uniform/choice`（`:1540-1556`） | 触发概率 `0.15` 与 `base_prob` 公式、幅度区间 |
| **相对基本面评分的随机项** | `uniform(-0.1,0.1)`（`:858`） | 分档边界（0.3/0.7 百分位）、`clamp ±0.5` |
| **整轮推进的最终股价** | 上述全部叠加 | **只能对拍边界与不变量**：`|changePct| ≤ 限幅`、价格 > 0、`volume = Σ 买单成交量` |

### 10.3 对 09 章的验收标准建议

| 档 | 验收方式 |
| --- | --- |
| **A 级（逐位）** | 合同引擎 / 计算图 / 撮合配对 / K 线（同平台）/ 财年定时器 / 归档导出 / 体检判定：**固定输入断言 `==`** |
| **B 级（边界 + 不变量）** | 定价链路：断言 `final ∈ [lower, upper]`、`pressure ∈ (-1,1)`、`\|drift\| ≤ happinessImpact*\|h\| + carbonImpact`、`volume` 一致性、封板判定线（±9.9）两侧的行为；导入：断言 append 幂等、overwrite 不删行、子行随父保留 |
| **C 级（统计）** | 做市商与随机事件：**固定种子后**断言 `==`（需新版引入显式 PRNG）；不固定种子则只断言分布区间与触发概率 |

> **唯一能让股票侧进入 A 级的做法**：把 `random.*` 全部换成按 `(competition_id, round, stock_id, purpose)` 派生的确定性流，
> 并把种子持久化进数据库。**这是产品决策，不是实现细节**。
