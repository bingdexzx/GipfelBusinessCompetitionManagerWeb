## 0. 先明确一件事：哪一个界面才是「可视化新建合同」

系统里有两个长得很像、但职责完全不同的入口，绝大多数"点了没反应 / 找不到按钮"的困惑都来自这里：

| 界面 | 路由 | 核心按钮 | 产出物 | 是否可视化 |
| --- | --- | --- | --- | --- |
| **合同类型管理** | `/contract-types` | **`可视化新建`** / `可视化编辑` | **合同类型模板**（全局，规则本身） | ✅ 节点画布编辑器 |
| 合同管理 | `/contracts` | `+ 新建` / `+ 新建合同` | **合同实例**（某场比赛下的一份合同） | ❌ 普通数据表单 |

结论：

- **「可视化新建合同」= 在「合同类型管理」页点 `可视化新建`**，用节点画布把合同规则（谁能签、要填什么、执行时改哪些字段、有哪些前置检查）画出来。
- 画布保存后得到的是**合同类型模板**，它还**不是一份真实合同**。必须再到「合同管理」页点 `+ 新建`，选这个类型、为每个参与方角色选公司，才会生成一份真实合同实例，然后补全编号、执行落账。
- 「简单新建」是同一件事的**低配表格版**（只能做"参与方 + 输入项 + 产业字段加减 + 产业字段比较"），不产出画布图。本文只讲可视化路径，简单模式仅在第 9 节对比。

一句话流程：

```
合同类型管理  ──「可视化新建」──▶  节点画布  ──「保存」──▶  合同类型模板（/api/contract-types）
                                                                    │
合同管理      ──「+ 新建」────▶  选类型 + 选公司 + 填数据  ──▶  合同实例（草稿）
                                                                    │
                                            补全各方编号  ──▶  待执行  ──「执行」──▶  落账（改写公司产业字段）
```

### 1.2 合同数据模型（三张表）

| 表 | 模型 | 作用域 | 关键点 |
| --- | --- | --- | --- |
| `contract_types` | `ContractType` | **全局**（无 `competitionId`） | 合同规则模板。`party_roles` / `input_schema` / `effects` / `conditions` / `graph` 全部以 **JSON 文本**存库 |
| `contracts` | `Contract` | **比赛级**（FK→Competition，级联删除） | 一份真实合同。状态机 `DRAFT → PENDING_EXEC → EXECUTED`，另有 `TERMINATED` |
| `contract_field_effects` | `ContractFieldEffect` | 跟随合同 | 落账审计行（不可变）。`op` ∈ ADD/SUB/SET，记录 `before_raw`/`after_raw`，供删除合同或终止合同时按 `executed_at` 重放复原 |

要点：

- `ContractType` 是全局的，**不绑定比赛**，所有比赛共用同一批合同类型。
- `ContractType.party_count` **不是独立配置项**：由 `partyRoles` 数组长度推导（保存时后端重算），列表页展示的"参与方数"也直接取 `partyRoles.length`。
- 合同实例的 `name` **不来自请求体**，创建时直接复制合同类型的 `name`（`serializers.py: ContractSerializer.create → name=ct.name`）。
- `Contract` 对 `ContractType` 是 `on_delete=RESTRICT`，且视图层额外拦截：**该类型下仍有合同实例时不允许删除类型**，报错会列出前 5 份合同名与比赛名。

## 2. 权限与入口：为什么按钮可能是灰的

### 2.1 三个权限键

| 权限键 | 控制什么 | 谁默认持有 |
| --- | --- | --- |
| `contractType:view` | 读合同类型（`GET /api/contract-types*`） | 全部角色的基础视图权限（`BASE_VIEW_PERMISSIONS`） |
| `contractType:manage` | **合同类型增删改（可视化新建的硬门槛）**、合同试算 | 超管；`COMPETITION_ADMIN` 仅在超管为其放开 `grantExtras` 后持有 |
| `contract:view` / `contract:audit` / `contract:execute` / `contract:manage` | 合同实例：查看 / 审核 / 执行 / 新建与删除 | `COMPETITION_ADMIN` 默认持有 audit + execute + manage；`PLAYER` 只有 view |

### 2.2 入口在哪里

- **侧边栏「合同类型管理」**（`/contract-types`）的菜单项门控条件是 `can('contractType:manage')`。也就是说：**只有能管理合同类型的人，才看得见这个菜单**。路由守卫同样要求 `contractType:manage`，手输 URL 也会被重定向到仪表盘。
- 因此：**如果你的侧边栏没有「合同类型管理」，就是没有 `contractType:manage` 权限**，不是 bug。请用超管账号，或在「账户管理」里给对应角色放开该权限（`COMPETITION_ADMIN` 需超管在 `grantExtras` 中放开）。

### 2.3 必须用电脑

`ContractTypeManageView.vue` 在最外层判断 `isPhone`：手机端**整页替换为提示**「请使用电脑打开该界面 / 该页面包含可视化编辑器，建议在电脑端操作」。手机上不但看不到画布，连表格和「简单新建」也看不到。

### 2.4 前置数据准备（缺一样后面都会卡）

| 前置项 | 在哪配 | 为什么需要 |
| --- | --- | --- |
| **比赛** | 比赛管理 | 合同实例挂在比赛下；合同管理页「新建」时会校验"请先在「比赛管理」中选择一个比赛" |
| **产业类型 + 字段** | 产业类型管理 | 可视化编辑器里的「产业字段」下拉、效果/检查的 `fieldKey` 全部来自这里 |
| **公司 + 公司所属产业类型** | 公司管理 | 合同参与方要选公司；"所选公司产业缺少效果字段"会直接阻止创建 |
| **地图节点与边** | 地图管理 | 只有用到 `nodeRoute`（节点列表）输入项时才需要；节点之间必须有连线 |

## 3. 可视化编辑器界面完全说明

点 `可视化新建` 后弹出一个**全屏对话框**（`el-dialog fullscreen`），标题为「可视化新建合同类型」。界面分四个区域：

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 顶部工具栏                                                                    │
│ [返回] [key(新建时只读/自动)] [名称] [保存] [源码 JSON] [自动布局] [试算] [清空] │
│ [－ 100% ＋ 适应] [🔍]               提示：拖动节点标题移动；点输出端口→点输入端口连线；点连线可删除 │
├────────────┬────────────────────────────────────────────┬────────────────────┤
│ 左侧节点库  │ 中间画布（可缩放/平移，点空白处拖拽平移）    │ 右侧属性面板        │
│ 声明        │  节点 = 带彩色标题栏的卡片                  │ 选中节点的全部可编辑项│
│  参与方     │  左边缘 = 输入端口，右边缘 = 输出端口        │ 未选中时提示"点击画布中│
│  输入项     │  端口旁标注「名称 + 类型」                   │ 的节点查看/编辑属性"  │

│  数值源     │  点击连线 = 删除该连线                       │ 勾选「源码 JSON」后，  │
│  计算       │  IF/FOREACH 节点可折叠（▼/▶）               │ 此处显示保存时将生成的 │
│  布尔比较   │                                            │ 四个 JSON 预览        │
│  列表运算   │                                            │                    │
│  字典运算   │                                            │                    │
│ 业务        │                                            │                    │
│  效果       │                                            │                    │
│  检查       │                                            │                    │
│ 控制流      │                                            │                    │
│  条件(IF)   │                                            │                    │
└────────────┴────────────────────────────────────────────┴────────────────────┘
```

### 3.1 顶部工具栏逐项说明

| 按钮 | 行为 |
| --- | --- |
| `返回` | 关闭编辑器（不保存） |
| `key` 输入框 | **仅新建时可见且只读**（占位符「自动生成（名称拼音）」）。编辑已有类型时该输入框**不显示**，key 不可改 |
| `名称` 输入框 | **仅新建时可见**。输入名称的同时实时用拼音生成 key（`toPinyinKey`：小写全拼、去声调、只保留 `a-z0-9_`） |
| `保存` | 校验 → 序列化 → POST（新建）或 PATCH（编辑）。见第 6 节 |
| `源码 JSON` | 在右侧面板底部显示保存时将写入的 `partyRoles / inputSchema / effects / conditions` 四个 JSON 预览 |
| `自动布局` | 按连线做分层排列（列间距 = 节点宽 288 + 80 = 368px） |
| `试算` | 打开右侧抽屉「合同试算面板」。**新建未保存时禁用**（`:disabled="!meta.id"`） |
| `清空` | 清空画布全部节点与连线（无二次确认，慎点） |
| `－ / 100% / ＋ / 适应` | 缩放、重置视图、适应全部内容 |
| `🔍` / `Ctrl+F` | 节点搜索栏（按 label / key / role 匹配，命中高亮、未命中变暗） |

### 3.2 连线操作（最容易踩坑的地方）

1. **点**源节点的**输出端口圆点**（右侧）→ 工具栏出现橙色提示「已选输出端口，请点击目标输入端口连线（再次点输出端口取消）」。
2. **点**目标节点的**输入端口圆点**（左侧）→ 连线建立。
3. 再点一次同一输出端口可取消选择。
4. 连线时**自动做类型检查**：

   - 类型匹配：连线为灰色实线，悬停提示「类型匹配：源类型 → 目标类型（点击删除连线）」。
   - **类型不匹配：连线变红色虚线并闪烁**，悬停提示「⚠ 类型不匹配：<原因>」，同时立即弹出 `ElMessage.warning`。
   - 注意：**类型不匹配只是告警，不拦截保存**。所以画布上的红线必须自己处理掉，否则运行期行为不符合预期。

5. **点击一条连线即可删除它**（没有右键菜单）。
6. 同一个输入端口只允许一条连线：给已被占用的输入端口连新线时，旧连线会被自动移除。
7. 端口圆点悬停会显示「名称（类型）：用途说明」，这是最权威的连线依据。
8. 拖动节点：按住**节点标题栏**拖（不是节点体；点节点体只是选中）。
9. 画布空白处拖动 = 平移视图；滚轮 = 缩放（位移会按当前缩放换算回世界坐标）。
10. 删除节点：标题栏右侧 `✕`，或右侧属性面板顶部的 `删除` 按钮。删节点会连带删掉它的所有连线。

### 3.3 节点的颜色与含义

| 节点 | 颜色 | 输入端口 | 输出端口 |
| --- | --- | --- | --- |
| 参与方 | 蓝 `#2980b9` | — | `输出`（参与方引用）、`公司名称`（字符串） |
| 输入项 | 青 `#16a085` | `上级`（控制流）、个别类型另有 `参与方`/`基建列表`/`载具列表` | `输出`，清单类另有聚合端点 |
| 数值源 | 橙 `#d35400` | 随"来源"变化（见 4.2） | `输出` |
| 计算 / 布尔比较 | 深青 `#117a8b` / 红 `#c0392b` | `值A`、`值B` | `输出`（比较为`布尔`） |
| 列表运算 / 字典运算 | 紫 `#8e44ad` / 青 `#16a085` | 随所选运算动态变化 | `输出` |
| 效果 | 红 `#c0392b` | `上级`、`参与方`、`值`、`值2` | 无（叶子动作） |
| 检查 | 绿 `#27ae60` | `上级`、`值1`、`值2`（旧版字段比较为 `参与方`+`值`） | 无 |
| 条件(IF) | 橙 `#e67e22` | `条件`、`上级` | `真分支`、`假分支` |

> 说明：`graph-model.ts` 里还保留 `根节点`、`遍历(FOREACH)`、`赋值(ASSIGN)`、`输出` 等类型的定义，用于解析历史数据；**当前版本左侧节点库不提供这些节点，无法从界面新建**。若某个历史合同类型的 `effects` 里本来就有 `FOREACH`，反序列化时它仍会在画布上渲染出来（可查看、可删除，只是不能再新增）。同理，`数值源` 的"来源"下拉当前只有 5 项。

## 4. 节点库详解：每个节点在右侧属性面板里怎么配

### 4.1 声明类

#### 参与方（`party`）

| 属性 | 说明 |
| --- | --- |
| 角色编码 `role` | 内部标识，新建节点时自动给 `party1`、`party2`…。效果/检查靠它绑定参与方 |
| 显示名 `label` | 创建合同表单里的字段标签 |
| 主办方 `isHost` | 打开后表示"主席团"。提示语：**主办方(主席团)不计产业字段；经济管理中心为普通参与方** |
| 可选 `selectable` | 默认开。关掉后该角色在创建表单里不作为可填项 |
| 限定产业 `industryTypeId` | 不填 = 不限；填了则该角色只能由指定产业类型的公司担任。列表页展示的"参与方数"就是参与方节点个数 |

**必须至少有一个非主办方参与方**，否则创建合同实例时后端直接拒绝（`validate_parties`：至少需要一个实际公司参与方）。

> ⚠️ **执行权的隐藏陷阱**：执行合同时会校验"合同的**最后一个非主办方参与方**公司必须在该账号的公司管理范围内"。所以**不要把主办方放在参与方列表的最后**，也不要把最后一方留给没有 `companyScopes` 的玩家账号，否则会出现"有 `contract:execute` 却执行不了"。

#### 输入项（`input`）

| 属性 | 说明 |
| --- | --- |
| 字段键 `key` | 内部标识，自动 `field1`、`field2`…。公式/输入取值靠它 |
| 显示名 `label` | 创建表单里的标签 |
| 类型 | 共 15 种，见下表 |
| 关联实体 `entityType` | 选清单类类型时会**自动写入**对应实体（如选"原料清单"自动 `MATERIAL`）；`ENTITY` 类型需手选 |
| 必填 `required` | 创建表单上显示红色星号（前端提示；后端不强制非空） |
| 默认值 | `dict`/`list` 用 JSON 文本框（必须先点输入框再改，不合法 JSON 会提示"默认值不是合法 JSON"）；清单类自动给 `{}`；`techNode` 给 `""` |
| 控制流上级 | 只读展示：若把某个 IF 的「真分支/假分支」连到了本节点的「上级」端口，则**创建合同时按条件显示/隐藏该字段**（不满足时字段被隐藏，且**不会提交该值**） |

**15 种输入项类型：**

| 下拉标签 | 内部值 | 自动关联实体 | 在创建合同表单里的控件 |
| --- | --- | --- | --- |
| 数字 | `number` | — | 大数输入框（`min=0`） |
| 文本 | `string` | — | 文本框 |
| 布尔 | `boolean` | — | 文本框 |
| 实体 | `ENTITY` | 需手选 | 实体下拉（按 `entityType` 懒加载，选中存 **id**） |
| 节点列表 | `nodeRoute` | 地图节点序列 | 有序节点编辑器：逐个添加、`↑`/`↓` 排序、`✕` 移除；**至少 2 个**；第 1 个任选，之后只能选与上一节点有连线的节点 |
| 地图节点 | `mapNode` | — | 下拉单选，**存节点名称字符串**（注意：与 `nodeRoute` 存 id 不同） |
| 列表 | `list` | — | `+ 添加元素` 行式编辑器（元素恒为**文本**输入框，无数字类型选项） |

### 4.2 数值类

#### 数值源（`value`）—— 5 种"来源"

| 来源 | 需要的输入端口 | 说明 |
| --- | --- | --- |
| 实体 `ENTITY` | `实体引用`（接输入项，取它的 key 作为实体 id）、`乘输入`（可选） | 实体属性 + `实体` 下拉 + `属性` 下拉（选项随实体变化）。运行时读该实体的真实属性；接了 `乘输入` 则为 `属性值 × 该输入项的值` |
| 产业字段 `FIELD` | `字段所属方`（接参与方） | 读**某参与方公司当前**的产业字段值。数字字段返回数字，列表/字典字段返回数组/对象。选中字段后输出端口类型会随字段数据类型变化 |
| 常量 `CONST` | `常量`（可选，接输入项则取它的默认值） | 常量值框可填数字或 JSON。有快捷按钮：`空字典 {}`、`空数组 []` |
| 公式 `FORMULA` | — | 表达式编辑器（见 4.2.1） |
| 产业类型判断 `INDUSTRY_IS` | `字段所属方`（接参与方） | 输出**布尔**：该参与方公司所属产业类型是否为所选产业。主办方/未绑定公司/未设产业类型 → `false`。可接给「条件(IF)」的 `条件` 端口 |

> 代码里还有 `VAR`、`ROUTE` 两种内部来源用于解析历史数据，但**下拉里选不到**。

**4.2.1 公式（FORMULA）编辑器**

- 大文本域（placeholder：`mathjs 表达式，作用域=输入项`），旁边实时做括号/引号配平校验，不配平时输入框变红并显示原因。
- `Ctrl+Space`（或 `Ctrl+空格`）触发自动补全下拉，候选 = 所有输入项 `key` + 函数名；`Ctrl+F` 是全局搜索节点。
- 面板下方提示「可用字段」＝所有输入项 key；「函数」＝ `round() max() min() abs() ceil() floor() sqrt() log() exp() pow()`。
- **实际运行期可用范围更大**（引擎 `safe_evaluate`）：输入项 key 之外还有内置辅助函数
  `IF(cond,a,b)`、`AND()`、`OR()`、`NOT()`、`len()`、`push()`、`concat()`、`contains()`、`indexIn()`、`keys()`、`values()`、`get()`、`has()`、`hasKey()`、`merge()`、`unique()`、`flatten()`、`join()`、`sumOf()`，
  以及 `+ - * / % ^ **`、比较、`! && ||`、一元负号、数组下标、括号。
- 求值失败会抛业务错误「公式求值失败: …」，合同执行/试算会直接失败（试算会把它显示为一条"试算中断"的失败检查）。
- 注意：公式是**自研受限求值器**，不是 `eval`，也不是第三方 `mathjs`（前端 placeholder 文案沿用了旧称）。

#### 计算（`calc`）/ 布尔比较（`compare`）

- 各有 `值A`、`值B` 两个输入端口，一个 `输出`（比较节点输出"布尔"）。
- 属性面板：`运算` 下拉（下方会按所选运算列出可填的"字面量(可选)"参数框，未连线的参数取该字面量）。
- 计算节点 → 接效果 `值`/`值2` 或检查 `值1`/`值2`；布尔比较节点 → 接「条件(IF)」的 `条件`。

**各节点可选运算（下拉里的中文标签，逐字来自 `OP_LABELS_FULL`）：**

- **列表运算**节点可选（20 项）：`追加元素`、`拼接多个列表`、`列表长度`、`是否包含元素`、`元素位置`、`去重`、`扁平化`、`列表求和`、`用分隔符连接`、`切片`、`反转`、`排序`、`生成整数区间`、`列表相加`、`列表相减`、以及三项通用运算 `长度(通用)`、`包含(通用)`、`求和(通用)`
- **字典运算**节点可选（13 项）：`取字典值`、`取全部键`、`取全部值`、`转键值对数组`、`是否含键`、`合并多个字典`、`由键值对造字典`、`由键列表造字典`、`键值互换`、`字典相加`、`字典相减`、`字典追加元素`、`字典求和`
- **计算**节点可选（8 项）：`加(+)`、`减(−)`、`乘(×)`、`除(÷)`、`指数(e^x)`、`对数(log)`、`取最小(min)`、`取最大(max)`
- **布尔比较**节点可选（6 项）：`等于(=)`、`不等于(≠)`、`大于(>)`、`小于(<)`、`大于等于(≥)`、`小于等于(≤)`

> 每个运算所需的参数端口见 `OP_ARG_SPECS`，端口中文名见 `OP_ARG_LABELS`（如 `列表`、`元素1`、`键`、`默认值`、`分隔符`、`起始/结束/步长`、`值A/值B`、`底数(默认e)`）。
> `指数(e^x)` 只吃一个参数（`操作数`）；`对数(log)` 吃 `操作数` + `底数(默认e)`（底数不填按自然对数）。
> 未连线的参数取属性面板里对应输入框的「字面量(可选)」；**字面量会被包成 `CONST` 传给引擎**，所以填 `PART` 这类字符串不会被误当数字 0。

### 4.3 业务类

#### 效果（`effect`）—— 合同执行时真正改数据的地方

| 属性 | 说明 |
| --- | --- |
| 运算 `op` | `ADD` 加(+) / `SUB` 减(-) / `SET` 设为(=) |
| 产业字段 `fieldKey` | 选/输入要改写的产业字段（列表里隐藏的字段也会出现，带 `·隐藏` 标注） |
| 组合方式 `valueOp` | 可选，`ADD` 加(+) / `SUB` 减(-) / `MUL` 乘(×)。**仅接 `值` 时不需要选** |

连线与语义：

- `参与方` 端口 → 接参与方节点：改**哪一方**的字段（运行时按其公司所属产业类型解析到具体字段）。
- `值` 端口 → 接数值源/输入项/运算节点：**写入量**。
- `值2` 端口 + `组合方式`：最终写入量 = `值 <组合方式> 值2`；只接 `值` 时退化为原行为。
- `上级` 端口 → 接 IF 的 `真分支/假分支`：挂在条件分支下。

> ⚠️ **保存时的强制校验**：所有 `kind=FIELD` 的效果必须连上有效的 `值` 来源。判定不通过（`值` 未连线，或来源是未选 key 的 INPUT，或 CONST 值为空）会**直接拒绝保存**并提示：
> 「存在 N 个「产业字段」效果未配置数值来源（值端口未连线或常量值为空），执行后不会改变任何字段。请为每个字段效果连接常量/输入/实体等数值节点后再保存。」
> 这是有意为之——漏接值端口时引擎会按 0 累加，合同"执行成功但字段毫无变化"极难排查。

#### 检查（`condition`）—— 6 种"种类"

| 种类 | 端口 | 语义 |
| --- | --- | --- |
| `VALUE_COMPARE` 数值比较（默认） | `值1`、`值2` | 两个自由数值源互相比较。可取两个公司的 FIELD 数值源，无需绑定固定字段 |
| `FIELD_COMPARE` 字段比较（兼容旧版） | `参与方`、`值` | 左操作数 = 该参与方公司的产业字段，右操作数 = 值端口连入的数值节点 |
| `INDUSTRY_IS` 产业类型核对 | `参与方` | 判断该参与方公司是否为所选产业类型 |
| `DICT_COMPARE` 字典比较 | `值1`、`值2` | **前提**：值一的每个键都必须存在于值二中（值一键 ⊆ 值二键），否则直接判不过；满足后对共有键逐一 `值1[k] op 值2[k]`，全满足才通过 |
| `LIST_COMPARE` 列表比较 | `值1`、`值2` | 比较**元素集合的包含关系**（非长度）：`ELEMENT_EQ` 元素相等（长度相同且逐位一致）、`CONTAINS` 被包含（值一 ⊆ 值二）、`GT` 真包含（值一 ⊃ 值二）、`GTE` 包含（值一 ⊇ 值二）、`EQ` 集合完全相同（双向包含） |
| —（通用属性） | — | `错误信息`：检查不通过时展示给用户的提示，留空用系统默认说明 |

**运算符可选范围（随种类变化）：**

- `VALUE_COMPARE`：`GTE` ≥、`LTE` ≤、`GT` >、`LT` <、`EQ` =、`CONTAINS` 包含、`HAS_KEY` 含键
- `DICT_COMPARE`：`GTE`、`GT`、`EQ`
- `LIST_COMPARE`：`ELEMENT_EQ`、`CONTAINS`、`GT`、`GTE`、`EQ`
- `FIELD_COMPARE`（旧版）：`GTE`、`LTE`、`GT`、`LT`、`EQ`
- 布尔比较节点：`CMP_EQ/NE/GT/LT/GTE/LTE`

> ⚠️ **列表/字典字段的数值比较陷阱**：`FIELD_COMPARE` 选中 `LIST`/`DICTIONARY` 类型字段时，属性面板会出现黄色告警——`≥ / ≤ / > / < / =` 比较的是**元素个数（长度）**，不是里面的数值。例如「合作伙伴列表 ≥ 3」意思是列表里至少 3 个元素。想判断内容是否包含某元素，应改用 `CONTAINS` / `HAS_KEY`。

检查节点也有 `上级` 端口：接 IF 的 `真分支/假分支` 后，该检查**只在所属分支成立时才执行**；分支不成立时跳过（不算失败、不阻塞）。

### 4.4 控制流

#### 条件(IF)（`if`）

- `条件` 端口：接能输出布尔值的节点——`布尔比较` 节点、`产业类型判断(INDUSTRY_IS)` 数值源、或 `检查` 节点。
- `真分支` / `假分支` 输出端口：接子节点（效果 / 检查 / 输入项）的 `上级` 端口。
- 同一个 IF 可以让**多个**子节点挂在同一分支下。
- IF 节点支持折叠：标题栏 `▼`/`▶`，折叠后显示「N 个节点已隐藏」徽标，便于画大图。

**IF 的两种用途（同一套连线，两条独立通路）：**

1. **输入项挂在 IF 分支下** → 控制**创建合同表单的字段显隐**（前端 `evalFormCondition` 实时求值，依赖未填字段时按 fail-open **显示**）。
2. **检查/效果挂在 IF 分支下** → 控制**执行时是否执行该检查/效果**（引擎按分支短路）。

### 加上"前置检查"

**目标**：成交数量 ≥ 1 才允许执行，否则给出自定义提示。

1. 左侧「业务」→ `+ 检查`。
2. 右侧属性面板：`种类` 选 `数值比较`、`比较` 选 `GTE`、`错误信息` 填例如「成交数量不足，无法履约」。
3. 连线：`qty 输入项` 的 `输出` → `检查` 的 `值1`。
4. 再放一个 `数值源`（`来源`=`常量`，`常量值`=`1`），其 `输出` → `检查` 的 `值2`。
5. 保存 → 到合同管理里新建一份合同并执行，条件不满足时会在预检/执行弹窗里显示自定义错误信息。

### 加上"条件分支"（进阶）

**目标**：只有当成交数量 ≥ 100 时，才执行上文的字段效果。

1. 左侧「数值」→ `+ 布尔比较`；右侧面板 `运算` 选 `大于等于(≥)`。
2. 连线：`qty 输入项` 的 `输出` → `布尔比较` 的 `值A`；常量 `100` 数值源的 `输出` → `值B`。
3. 左侧「控制流」→ `+ 条件(IF)`。
4. 连线：`布尔比较` 的 `布尔` → `IF` 的 `条件`。
5. 连线：`IF` 的 `真分支` → `效果` 的 `上级`。
6. 保存后试算：数量 < 100 时该效果应被跳过；≥ 100 时生效。

### 让输入字段按条件显隐（进阶）

把上面的 `IF` 的 `真分支` 改成连到**某个输入项节点的 `上级` 端口**，该输入项就只在条件成立时出现在"新建合同"表单里，且不满足时**不会被提交**。注意表单期只能静态求值 `INPUT` / `CONST` / `INDUSTRY_IS` / `FIELD` / 部分 `OP`；`FORMULA`、`ENTITY`、`ROUTE` 在表单期无法判定 → 按**显示**处理（fail-open）。

### 用清单输入项自动算总价（进阶）

1. 放一个 `输入项`，`类型` = `基建清单`（自动关联实体 `INFRASTRUCTURE`）。
2. 该节点出现多个输出端口。把 `基建总价格` 端口 → `效果` 的 `值`。
3. 这样引擎会按比赛自动计算 `Σ(基建价格 × 输入数量)`，**不需要**手工拆解每一项。
4. 若只想让用户选特定几个基建：再放一个 `数值源`（`来源`=`常量`，`常量值` = `["基建A","基建B"]`），把它的 `输出` → 基建清单节点的 `基建列表` 端口。

## 6. 保存时到底发生了什么（数据契约）

点 `保存` 后，前端做三件事：

### 6.1 校验

| 校验 | 触发条件 | 结果 |
| --- | --- | --- |
| 名称为空 | 新建且 `meta.name` 为空 | 警告「请填写名称」，不提交 |
| key 兜底 | 新建且 key 为空（名称全是符号等） | 用名称拼音现算一次 key |
| **效果缺值来源** | 存在 `kind=FIELD` 的效果，其 `值` 既没连线、常量又为空 | **错误并拒绝保存**（见 4.3） |

> 注意：编辑器**不校验**"是否至少有一个参与方 / 一个效果 / 一个输入项 / 是否有类型不匹配的红线"。这些是运行时才会暴露的问题（后端 `serializers` 也不校验参与方是否为空，只有创建**合同实例**时才要求"至少一个非主办方参与方"）。所以**每次保存后都应该点一次 `试算`**。

### 6.2 序列化：图 → 四个 JSON

编辑器内部维护的是 `{nodes, edges}` 图结构，保存时调用 `graphToFlat(graph)` 展平成后端引擎消费的四个数组：

```jsonc
{
  "partyRoles": [ { "role": "...", "label": "...", "isHost": false, "selectable": true, "industryTypeId": null } ],
  "inputSchema": [ { "key": "...", "label": "...", "type": "number|materialList|...",
                     "entityType": null, "required": true, "default": null,
                     "party": null,                 // 清单输入源连了参与方时的角色
                     "allowedInfrastructures": null, // 基建清单的「基建列表」限定
                     "allowedVehicles": null,        // 载具清单的「载具列表」限定
                     "branch": { "when": "then|else", "cond": {...} } } ],
  "effects": [ /* 效果树，可嵌套 IF / FOREACH */ ],
  "conditions": [ /* 检查数组 */ ]
}
```

**效果树（effects）的形状：**

```jsonc
// 叶子：产业字段效果
{ "kind": "FIELD", "party": "buyer", "fieldKey": "location", "op": "ADD",
  "valueOp": null,                                  // 可选：ADD/SUB/MUL
  "value":  { "type": "OP", "op": "MUL", "args": [ {"type":"INPUT","key":"qty"}, {"type":"CONST","value":"100"} ] },
  "value2": undefined }                             // 仅在连了 值2 时出现

// 分支（顶层效果按画布 y 再按 x 排序；挂在 IF 下的效果不进入顶层）
{ "kind": "IF", "cond": {...}, "then": [ /* 效果 */ ], "else": [ /* 效果 */ ] }
{ "kind": "FOREACH", "items": {...}, "var": "item", "body": [ /* 效果 */ ] }
{ "kind": "ASSIGN", "name": "...", "value": {...} }
```

**数值来源（ValueSpec）的可能形状：**

| `type` | 载荷 | 来源 |
| --- | --- | --- |
| `CONST` | `value`（数字，或 JSON 数组/对象字符串） | 常量数值源、运算节点的未连线字面量 |
| `INPUT` | `key`，可选 `aggregate`（聚合口径）、`party`（价格按所在地取） | 输入项直连，或经数值源 `输入键` 端口。**聚合口径由连的是哪个源端口决定**（如 `warehouseStorage` → `WAREHOUSE_STORAGE`） |
| `FIELD` | `party`、`fieldKey` | 产业字段数值源 |
| `ENTITY` | `entityType`、`entityRef`（输入项 key）、`attribute`、`multiplyByInput` | 实体数值源 |
| `FORMULA` | `expr` | 公式数值源 |
| `INDUSTRY_IS` | `party`、`industryTypeId`（布尔） | 产业类型判断数值源 |
| `OP` | `op`、`args[]` | 计算 / 布尔比较 / 列表运算 / 字典运算节点 |
| `ROUTE` | `routeRef` | （历史数据） |
| `VAR` | `name` | （历史数据） |
| `PARTY_COMPANY_NAME` | `party` | 参与方节点的 `公司名称` 端口直连 |

**检查（conditions）的形状：**

```jsonc
{ "kind": "VALUE_COMPARE", "label": "", "errorMessage": "数量不足", "op": "GTE",
  "value1": {...}, "value2": {...},
  "branch": { "when": "then", "cond": {...} } }        // 挂在 IF 分支下时才有

{ "kind": "INDUSTRY_IS", "party": "buyer", "industryTypeId": 4, "errorMessage": "..." }
{ "kind": "DICT_COMPARE" | "LIST_COMPARE", "op": "GTE", "value1": {...}, "value2": {...} }
{ "kind": "FIELD_COMPARE", "party": "...", "fieldKey": "...", "op": "GTE", "value": {...} }  // 旧版
```

### 6.3 落库与广播

请求（`contractTypesApi`）：

| 场景 | 请求 |
| --- | --- |
| 新建 | `POST /api/contract-types`，体 = `{ key, name, partyRoles, inputSchema, effects, conditions, graph }` |
| 编辑 | `PATCH /api/contract-types/:id`，体 = `{ partyRoles, inputSchema, effects, conditions, graph }`（不发 key/name） |

后端处理：

1. 权限：`contractType:view`（GET）/ `contractType:manage`（POST/PATCH/DELETE），且 `@no_competition_scope`（**全局资源，不受比赛域隔离**）。
2. 校验：`key`、`name` 去空格后不能为空；key 已存在则报错「合同类型 key 已存在: <key>」。
3. `party_count` 由 `partyRoles` 长度**重算**后入库。
4. 五个 JSON 字段以 `json.dumps(ensure_ascii=False)` 存为**文本**；`graph` 为 `null` 时存 `NULL`。
5. 写库触发 `post_save` → `apps/common/signals.py` 按 `MODEL_TO_RESOURCE` 广播 `contract-types`（scope=`global`）→ 其他客户端的合同类型管理页通过 `useResourceChanged("contract-types", …)` 自动刷新。
6. 前端收到成功 → `ElMessage.success("已创建" / "已保存")` → 关闭对话框 → 重新 `load()` 列表。

> `graph` 字段是**纯前端资产**：后端只存不解析，引擎完全不看它。引擎只消费 `partyRoles` / `inputSchema` / `effects` / `conditions`。所以即使 `graph` 丢了，合同依然能执行；反之 **只改库里的 `effects` 而不改 `graph`，下次用可视化编辑打开会覆盖掉你的手改**（因为保存时 `graph` 会被整体重写）。

## 7. 第二步：从合同类型生成真实合同（`/contracts`）

### 7.1 进入与前置

- 侧边栏「合同管理」/「合同」（`canAny(['contract:view','contract:execute','contract:manage'])`）。
- 页面上方若显示「请先在「比赛管理」中选择一个比赛」，说明当前没有选中比赛，点 `+ 新建` 会被拦下。
- `+ 新建` 按钮仅在 `can('contract:manage')` 时出现。**注意提示文案与实际判据不一致**：代码判断的是 `contract:manage`，但警告文案写的是「仅超级管理员可创建合同」。实际后端 `POST /api/contracts` 要求 `contract:manage`，且非超管只能在自己所属比赛下创建。

### 7.2 表单怎么填

点 `+ 新建` 弹出「新建合同」对话框（宽 640px）：

1. **合同类型**（必选，可搜索）：只能选到 `enabled=true` 的类型（前端用 `contractTypesApi.list(true)`）。选中后表单**动态展开**参与方与输入项。
2. **参与方**：按 `partyRoles` 逐行渲染。
   - 主办方行：只显示灰色文字「主席团」，不需要选公司。
   - 非主办方行：`选择公司` 下拉（可搜索）+ `合同编号` 输入框（**可留空**）。
   - 公司下拉来自 `GET /companies?competitionId=…`；持 `contract:manage` 时额外带 `unscoped=1`，因此能选到本比赛内的**任意**公司（不受 `viewCompanyScopes` 限制）。
3. **合同数据**（分隔线以下）：按 `inputSchema` 逐项渲染，控件取决于字段 `type`（见 4.1 的 15 种类型表）。
   - `节点列表`：至少 2 个节点，第 2 个起必须与前一节点有连线，否则点确定时会提示「「X」中「A」与前一节点「B」之间没有连线，请调整」。
   - 挂在 IF 分支下的字段：条件不满足时**不渲染**，提交时也**不带该值**。
4. 点 `确定创建`。

### 7.3 创建前的两道自动拦截

| 拦截 | 触发 | 表现 |
| --- | --- | --- |
| 未选合同类型 | `contractTypeId` 为空 | 警告「请选择合同类型」 |
| 参与方未选公司 | 任意非主办方角色没选公司 | 警告「请为「<显示名>」选择公司」 |
| 节点列表断链 | 见上 | 警告并阻止 |
| **产业不支持该合同** | 所选公司所属产业**缺少效果所引用的 `fieldKey`** | 弹出「所选参与方公司所属产业缺少合同所需字段，无法创建该合同」对话框，并列出缺失字段表格，**阻止创建** |

> "产业不支持"是最常见的创建失败原因。它说明：合同类型里的效果选了 `fieldKey = X`，但该参与方公司所属的产业类型里没有 `X` 这个字段。修法：改选公司、或到产业类型管理给该产业补字段、或改合同类型的字段选择。

### 7.4 创建结果与状态

创建请求体：

```json
{ "competitionId": 4, "contractTypeId": 3,
  "parties": [ { "role": "seller", "companyId": 1, "isHost": false, "contractNumber": null },
               { "role": "host",   "companyId": null, "isHost": true,  "contractNumber": null } ],
  "inputs":  { "qty": 10 } }
```

返回后的状态规则（前后端在同一套规则上）：

- 合同 `name` = 合同类型 `name`；初始状态 `DRAFT`。
- **若创建时全部非主办方参与方的编号都已填写**（典型是单方合同）→ 后端直接把状态置为 `PENDING_EXEC`，前端提示「合同已创建，编号已齐备，进入待执行状态」。
- 否则保持 `DRAFT`，提示「合同已创建（草稿），请在详情页补全其余各方编号后执行」。

### 7.5 补编号、预检、执行

| 操作 | 位置 | 权限 | 关键规则 |
| --- | --- | --- | --- |
| 补全编号 | 列表 `详情` → 参与方表格内联编辑 | `contract:audit`（且公司在自己 `companyScopes` 内）/ `contract:execute` / `contract:manage` | 仅 `DRAFT` 状态可编辑；主办方不可编辑；全部非主办方编号齐备后状态自动升为 `PENDING_EXEC`，有编号被清空则退回 `DRAFT` |
| 预检 | 待补充 | `contract:audit` 及以上 | `POST /api/contracts/:id/precheck`，跑检查但不落账 |
| 执行 | 列表 `执行` 按钮（绿色，仅 `canExecuteRow` 时出现） | `contract:audit` 及以上 | 见下 |
| 删除 | 列表 `删除`（仅超管可见） | `contract:manage` **且** `role == SUPER_ADMIN` | 两步确认；会先按 `executedAt` 重放复原已落账的字段效果，再删合同 |

**执行（会签落账）的完整前置条件：**

1. 状态不能是 `EXECUTED`（「合同已执行，不可重复执行」）或 `TERMINATED`（「合同已终止，不可再次执行」）。
2. 所有非主办方参与方都必须已编号，否则「存在未编号的参与方，无法执行：角色 <role>」。
3. 执行方范围：非超管需持有 `contract:execute` / `contract:audit` / `contract:manage` 任一，**且合同的最后一个非主办方参与方公司必须在其 `companyScopes` 内**，否则「仅具有合同参与公司管理权的账号可执行」。
4. 并发安全：以「仅当状态非 EXECUTED/TERMINATED 才原子抢占为 EXECUTED」保证并发请求只有一个真正落账。
5. 落账内容：引擎按 `effects` 改写字段并写 `contract_field_effects` 审计行，写 `execution_log` / `execution_result`，推进 `updated_at`，触发受影响公司的计算字段级联重算，并广播 `company-field` 与 `contracts` 让各端实时刷新。
6. 执行时可以覆盖输入参数（`POST /api/contracts/:id/execute` 的 body 里带 `inputs`）。

## 8. 试算面板（可视化编辑器内置的验证工具）

- 位置：可视化编辑器工具栏 `试算`（**必须先保存过一次类型**，新建未保存时为禁用）。
- 用法：选一个「测试公司」→ `运行试算`。返回两块结果：
  - **检查结果**：逐条列出 `✓ / ✗`、标签、以及不通过时的 `errorMessage`。
  - **效果预览**：逐条列出 `fieldKey` + `运算`（带写入值）。
- 语义细节：
  - 后端把**全部非主办方角色都绑定到你所选的同一个测试公司**（主办方无公司）。所以"需要两家不同公司"的合同，试算结果只能作为参考。
  - 输入取 `inputSchema` 各字段的 `default`（`default` 为 `null` 的字段不参与），可被请求里的 `inputs` 覆盖。
  - 整个流程在事务内执行后**整体回滚**：字段改写、效果记录、`on_commit` 广播全部丢弃，不留痕迹。
  - 引擎报错不会 500，而是转成一条 `kind="TRIAL"`、`label="试算中断"` 的失败检查返回——**这是定位配置错误最快的入口**。
  - 权限：`contractType:manage`；非超管只能试算自己比赛范围内的公司。

## 9. 可视化新建 vs 简单新建 vs 直接改 JSON

| 维度 | 可视化新建 | 简单新建 | 手工改库 / admin |
| --- | --- | --- | --- |
| 入口 | 合同类型管理 → `可视化新建` | 合同类型管理 → `简单新建` | `/admin`（Django Admin） |
| 能表达的检查 | 6 种（数值/字段/产业/字典/列表比较） | 1 种（`FIELD_COMPARE` 产业字段比较） | 任意 |
| 能表达的效果 | 效果树（含 IF / 运算 / 清单聚合 / 公式） | 只有叶子 `FIELD` 效果，值为常量或简单公式 | 任意 |
| 能否条件显隐输入项 | ✅ | ❌ | 可以（手写 `branch`） |
| 关键副作用 | 保存时**整体重写 `graph`** | 保存时**原样保留**原 `graph`（`graph: props.contractType?.graph \|\| null`），并原样保留非 `FIELD_COMPARE` 的检查 | 不广播实时刷新、绕过全部校验 |

**简单模式的隐藏行为（重要）**：简单编辑器只能编辑 `FIELD_COMPARE` 检查，加载时会把其它种类的检查放进 `preservedConditions` **原样保留**，并在界面上提示「该合同类型含有专家模式创建的其它检查（非「产业字段比较」），已在保存时原样保留，不会在简单模式下编辑」。但它对 `effects` 只保留 `type === 'FIELD'` 的项——**用它去编辑一个用可视化模式做的复杂合同，会丢掉 IF/FOREACH 等非叶子效果**（`graph` 仍在，重新用可视化编辑打开时会以 `graph` 为准，所以损失通常可恢复，但千万不要在简单模式下"保存后再也不打开可视化"）。

> ⚠️ Django Admin（`/admin`）虽然能直接改这些 JSON 字段，但会**绕过合同引擎与权限派生**，也可能与 `graph` 不一致（下次可视化编辑会把你的手改覆盖掉）。常规操作请走前端。

## 10. 排错清单（按现象查）

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 侧边栏没有「合同类型管理」 | 没有 `contractType:manage` | 换超管账号，或在账户管理给该角色放开该权限 |
| 手机打开 `/contract-types` 只有一句提示 | 页面按 `isPhone` 整页替换 | 用电脑打开 |
| 点 `可视化新建` 没反应 | 按钮被 `:disabled="!authStore.can('contractType:manage')"` 禁用 | 同上；注意被禁用的按钮点了不会有任何提示 |
| 保存报「合同类型 key 已存在」 | key 由名称拼音生成，重名类型会产生同一个 key | 改名称，或用「简单编辑」之外的方式新建一个名称不同的类型（key 生成后不可改） |
| 保存报「请填写名称」 | 名称空 | 填名称 |
| 保存报「存在 N 个「产业字段」效果未配置数值来源…」 | 效果节点的 `值` 端口没连线 | 给每个效果接上常量/输入/实体等数值节点 |
| 画布上有红色闪烁虚线 | 连线两端数据类型不匹配（仅告警，不拦截保存） | 悬停看原因，改接正确端口 |
| 合同"执行成功"但字段没变 | 效果写入量算出来是 0（漏接值端口的历史类型、或公式恒为 0、或常量填了空） | 用 `试算` 看「效果预览」的写入值 |
| 执行报「存在未编号的参与方，无法执行：角色 X」 | 还没补全编号 | 到详情页补编号 |
| 执行报「仅具有合同参与公司管理权的账号可执行」 | 该账号 `companyScopes` 不含"最后一个非主办方参与方"的公司 | 调整参与方顺序/换账号/配置 `companyScopes` |
| 创建合同被弹「所选参与方公司所属产业缺少合同所需字段」 | 效果引用的 `fieldKey` 在该公司产业类型里不存在 | 补产业字段 / 换公司 / 改合同类型 |
| 创建合同提示「请先在「比赛管理」中选择一个比赛」 | 没选比赛 | 到比赛管理选一个 |
| 试算按钮是灰的 | 类型还没保存过（`meta.id` 为空） | 先 `保存`，再点 `试算` |
| 简单编辑保存后复杂检查/效果被改动 | 简单模式只保留 `FIELD` 效果与 `FIELD_COMPARE` 检查 | 复杂合同只用可视化模式编辑 |
| 合同类型删不掉 | 该类型下有合同实例（`RESTRICT` + 视图层拦截） | 按报错列出的合同先删实例（删合同仅超管可做） |
| 两个人在改同一个类型，后保存的把前者覆盖 | 合同类型 PATCH **没有乐观锁/版本号** | 避免并发编辑同一类型 |
| 改完入库的 JSON 后又用可视化编辑打开，改动没了 | 保存时 `graph` 被整体重写，前端以 `graph` 为准 | 要手改就同时改 `graph`，或只用可视化模式维护 |
