# 比赛 Excel 建包教程（从空表到一场能打的比赛）

> 这份教程带你**从零**用表格文件建出一场比赛：填表 → 检查 → 建比赛 → 导入 → 验收。
> 全程不需要写代码，也不需要装任何东西（仓库自带的 Python 环境足够）。
>
> 配套文件：
> - 参考手册（逐表逐列的字段字典）：[比赛 Excel 建包规范](比赛Excel建包规范.md)
> - 空白模板：`backend/examples/excel/比赛建包模板.xlsx`
> - 汽车产业链完整示例：`backend/examples/excel/汽车产业链示例.xlsx`
> - 最小可用示例（本教程第 1 节）：`backend/examples/excel/最小示例.xlsx`

## 0. 先搞清楚三件事

1. **一张工作表 = 一类内容**。你要建什么就放哪张表；没放的表**完全不参与产出**。
   这就是「用不同的表隔离不同内容」：战术表、公司表、合同表可以分别给不同的人维护。
2. **表头是中文的**，不要改。程序也接受英文参数名（老文件兼容），但同一列不要写两遍。
   中文表头 ↔ 参数名的完整对照在「规范」文档里，模板的「说明」表里也有一份。
3. **表里的内容不会直接写库**：程序先把它翻译成「比赛建包库」的调用、产出归档，
   再走既有的导入引擎落库。所以既有语义（比赛隔离、追加/覆盖、空比赛保护、预演回滚）全都适用。

### 最小示例里有什么

| 表 | 内容示例 |
| --- | --- |

| 产业类型 | `9001 原料开采`、`9002 零件加工` |

## 2. 认识工作簿

### 2.1 表的清单与顺序

表在文件里的**先后顺序不影响结果**（程序按依赖顺序处理）。常用的表：

| 分组 | 表 |
| --- | --- |
| 比赛自身 | 比赛、财年 |
| 行业口径 | 产业类型、产业字段 |
| 参赛主体 | 区域、公司、公司字段值 |
| 地理与物流 | 地图节点类型、路径类型、地图节点、地图连线 |
| 物资与产能 | 燃料、原料、科技、生产线、基建、仓库、零件、产品、载具 |
| 科技与需求 | 消费者需求 |
| 市场与规则 | 区域总览卡片、合同类型、合同实例、消息 |
| 账号 | 账号 |

**股票系统不在规范内**：没有股票 / 资金账户 / 股票参数三类表（按要求不动股票系统）。

### 2.2 填写规则（背下这 6 条就够用）

| 想表达 | 就写 |
| --- | --- |
| 布尔 | `是` / `否`（也认 `TRUE/FALSE`、`1/0`、`y/n`） |
| 列表 | `公路;铁路`（分号、顿号、逗号、换行都行） |
| 配比 / 地点价 | `锂矿石*4; 铝土矿*1`、`白云鄂博矿区:180; 上游集运站:195` |
| 合同输入项 | `quantity=20; royalty_rate=60`；复杂值直接写 JSON：`goods={"锂矿石": 20}` |
| 复杂结构 | 以 `{` 或 `[` 开头的单元格按 JSON 解析 |
| 注释 / 空行 | 行首写 `#` 或 `//`；整行空白自动忽略 |

金额、单价、数量**建议直接写数字文本**（`600000`、`0.35`），程序按文本保精度。

### 2.3 空单元格 = 不填这个参数

没写的列会用建包库的默认值（例如 `产业字段` 的 `字段类型` 留空 = `NUMBER`）。
**唯一的例外是「合同实例」的输入项**：引擎执行时**不会**套用默认值，
所以每个输入项都要在表格里写明（见 3.7）。

## 3. 手把手：建一场汽车产业链比赛

下面每一步都可以在模板 `比赛建包模板.xlsx` 上直接做（模板里每张表都有表头 + 一行示例 + 空行）。
完整成品见 `汽车产业链示例.xlsx`。

### 3.1 比赛 + 财年

| 比赛名称 | 状态 |
| --- | --- |
| 2026 汽车产业链测试赛 | ACTIVE |

| 年份 | 状态 |
| --- | --- |
| 2026 | ACTIVE |

- 比赛名**全局唯一**：`--create-competition` 遇到同名比赛会复用而不是新建。
- 建比赛时不会改名已有比赛；`--name` 可以覆盖表里的名字（做多份分表时有用）。
- 财年从非 ACTIVE 改成 ACTIVE 会触发 `FY_START` 定时器字段——如果产业字段里配了定时器，注意顺序。

### 3.2 产业口径（产业类型 + 产业字段）

先定「有哪些产业」（`编码` 全局唯一，跨比赛复用，不要给不同行业用同一个编码）：

| 编码 | 产业名称 | 说明 |
| --- | --- | --- |
| 2001 | 原料开采 | 汽车产业链上游：锂 / 铝 / 铁矿石与橡胶硅砂开采 |
| 2002 | 零部件加工 | 汽车产业链中游：原材料加工合成零部件 |
| 2003 | 整车进销 | 汽车产业链下游：零部件合成整车并进销 |

再给每个产业配字段（**这是全场最需要想清楚的一张表**，合同、卡片、图表都按 `字段键` 绑定）：

| 所属产业 | 字段名称 | 字段键 | 字段类型 | 默认值 | 是否计算字段 | 计算图 | 类型配置 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 2001 | 所在地 | location | STRING | | | | |
| 2001 | 现金 | cash | NUMBER | 0 | | | |
| 2001 | 库存台账 | inventory | DICTIONARY | {} | | | NUMBER |
| 2001 | 货币资金 | total_cash | NUMBER | | 是 | cash + bank_deposit | |
| … | … | … | … | … | | | |

要点：

1. **每个产业都要有一个 `所在地`（`location`）字段**：地图、运费、区域总览都依赖它。
2. `字段键` 用英文（公式里要当变量名用）；`字段名称` 才是给人看的中文。
3. **字典字段**（`DICTIONARY`）用来记库存这类 `{名称: 数量}`，`类型配置` 写 `NUMBER` 表示值是数字。
4. **计算字段**：勾「是」后必须在 `计算图` 里写公式。最常用的是求和，直接写 `cash + bank_deposit`
   （多个字段相加会自动串起来）；复杂图可以直接贴 GGraph JSON。
5. 计算字段与「财年定时器」互斥；定时器字段要同时填 `启用财年定时器=是`、`定时器时机`、`定时器写入值`。

### 3.3 区域与公司

| 区域名称 | 说明 |
| --- | --- |
| 上游资源区 | 锂 / 铝 / 铁矿与橡胶硅砂资源带 |
| 中部智造区 | 动力电池、电驱与轻量化车身产业带 |
| 东部车都 | 整车制造、展销与出口集散地 |

公司表的**前 4 列是固定的**（公司名称 / 所属产业 / 所属区域 / 状态），
**后面你自己加的列会被当作这家公司的产业字段初始值** —— 列名写字段名称（中文）或字段键（英文）都行：

| 公司名称 | 所属产业 | 所属区域 | 状态 | 所在地 | 现金 | 银行存款 | 许可配额 | 库存台账 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 西岭锂业 | 原料开采 | 上游资源区 | ACTIVE | 白云鄂博矿区 | 1200000 | 300000 | 800 | {"原矿": 120, "锂矿石": 40} |
| 戈壁铝业 | 原料开采 | 上游资源区 | ACTIVE | 戈壁铝土矿区 | 900000 | 200000 | 600 | {"原矿": 80} |
| 中原创能 | 零部件加工 | 中部智造区 | ACTIVE | 中部智造园 | 1500000 | 500000 | 600 | {"货物": 60} |

- `所在地` 里写的是**地图节点名**（货款按卖方所在地价结算就靠它）。
- 想让某家公司的字段分散维护，就用「公司字段值」表：`公司名称 | 字段键 | 值`，
  与公司表并用时**后写的覆盖先写的**（公司表先处理）。
- `所属产业` 可以写编码（`2001`）也可以写名称（`原料开采`）。
- 字段写错会立刻报错：`未知字段「现金x」：既不是字段键，也不是任何产业字段的显示名`。

### 3.4 地图与物流

| 节点名称 | 节点类型 | 所属区域 | X坐标 | Y坐标 |
| --- | --- | --- | --- | --- |
| 白云鄂博矿区 | 矿区 | 上游资源区 | 140 | 120 |
| 上游集运站 | 物流枢纽 | 上游资源区 | 360 | 300 |
| 中部智造园 | 产业园区 | 中部智造区 | 620 | 300 |

| 起点节点 | 终点节点 | 距离(公里) | 路径类型 |
| --- | --- | --- | --- |
| 白云鄂博矿区 | 上游集运站 | 120 | 公路 |
| 上游集运站 | 中部智造园 | 420 | 铁路 |

- 需要先用「地图节点类型」「路径类型」两张表把这些**类型名**建出来。
- 节点的 `所属区域` 是**文本**（不是外键），区域总览按它把公司/节点归到区域。
- 同一对「起点 + 终点」只能有一条连线；反向是另一条（`A→B` 与 `B→A` 可以同时存在）。
- 孤立节点（没有任何连线）不可达，运输合同算不出路程 —— `--inspect` 的体检提醒会点出来。

### 3.5 物资与产能

依赖方向是固定的：**原料 → 零件 → 产品**（零件配方只能引用原料，产品配方只能引用零件）。

| 表 | 关键列 | 示例 |
| --- | --- | --- |
| 燃料 | 燃料名称 / 每升单价 | `柴油` / `7.6` |
| 原料 | 原料名称 / 产地 / 碳排系数 / 类型 / 地点价 | `锂矿石` / `白云鄂博矿区` / `0.52` / `NORMAL` / `白云鄂博矿区:180; 上游集运站:195` |
| 科技 | 科技名称 / 层级 / 研发费用 / 前置科技 | `整车平台化` / `2` / `200000` / `电池成组技术; 电驱系统集成` |
| 零件 | 零件名称 / 原料配比 / 所需科技 | `动力电池包` / `锂矿石*4; 铝土矿*1` / `电池成组技术` |
| 产品 | 产品名称 / 零件配比 / 所需科技 | `纯电轿车` / `动力电池包*1; 驱动电机*1` / `整车平台化` |
| 生产线 | 生产线名称 / 单价 / 用工人数 / 年产能 | `电芯产线` / `2400000` / `120` / `6000` |
| 基建 | 基建名称 / 占地面积 / 单价 / 启用费用 / 6 项加成 | `光伏电站` / `160` / `1200000` / `50000` / … / `0.12` |
| 仓库 | 仓库名称 / 仓库种类 / 容量 / 单价 | `原料仓` / `MATERIAL` / `30000` / `400000` |
| 载具 | 载具名称 / 燃料 / 可通行路径类型 / 每公里油耗 / 载货量 / 单价 / 碳排系数 | `重型卡车` / `柴油` / `公路` / `0.35` / `30` / `260000` / `0.9` |

- **地点价**是「同一原料在不同节点不同价」的来源；合同里按卖方所在地取价时会用到。
- 载具**必须绑燃料**，并且至少有 `一条可通行路径类型`，否则运输路径校验会失败。
- 仓库四种种类（`MATERIAL/PART/PRODUCT/FUEL`）建议都建，否则对应物资无处存放。

| --- | --- | --- | --- |

### 3.7 合同（最容易踩坑的一节）

**合同类型**（全局模板）两种写法，二选一：

**写法 A：引用代码脚本（推荐）** —— 复杂逻辑留在 `.py` 里，表格只写路径：

| 类型标识 | 合同名称 | 说明 | 脚本路径 |
| --- | --- | --- | --- |
| auto-mining | 开采合同 | 开采企业缴纳权利金并入库原矿 | examples/contracts/auto_chain_contracts.py |

**写法 B：直接贴四份 JSON** —— 适合简单合同（见最小示例）：

| 类型标识 | 合同名称 | 参与方 | 输入项定义 | 效果定义 | 前置检查 |
| --- | --- | --- | --- | --- | --- |
| mini-sale | 简易购销合同 | seller=卖方; buyer=买方 | `[{"key":"amount","label":"成交金额","type":"NUMBER","required":true,"default":"1000"}]` | `[{"kind":"FIELD","party":"buyer","fieldKey":"cash","op":"SUB","value":{"type":"INPUT","key":"amount"}},{…"party":"seller","op":"ADD"…}]` | `[{"kind":"FIELD_COMPARE","party":"buyer","fieldKey":"cash","op":"GTE","value":{"type":"INPUT","key":"amount"}}]` |

三个必须知道的坑（都是引擎既有语义）：

1. **效果的取值范围必须写 `{"type": "INPUT", "key": "amount"}`**。
   项目文档和 `demo_competition.py` 里的 `{"from": "input", "key": "amount"}` 引擎不认，
   会**静默按 0 计算**（表现是「金额恒为 0」）。表格工具会自动把它归一成 `{"type":"INPUT"}` 并提示你。
2. **前置检查的种类是 `FIELD_COMPARE`**（不是 `FIELD`）。写成 `FIELD` 检查会**恒不通过**。
   表格工具同样会自动归一并提示。
3. **合同实例的输入项要填全**：引擎执行时不套用 `default`，没填的输入项按 0 参与运算。

**合同实例**（比赛内的预置合同）：

| 合同类型标识 | 合同名称 | 参与方 | 输入项 | 状态 |
| --- | --- | --- | --- | --- |
| mini-sale | 简易购销合同 | seller=甲矿场\|S-001; buyer=乙工厂\|B-001 | amount=1200 | DRAFT |

- 参与方写法：`角色=公司名|合同编号`（编号可省），角色名必须与合同类型的「参与方」对得上；
  主办方角色（`|host`）在实例里**不用写**。
- 输入项写法：`key=value`，复杂值直接写 JSON（`goods={"锂矿石": 20}`）；也可以整格写 JSON。
- **状态保持 `DRAFT`**：`EXECUTED` 会立刻改写公司字段并落账，开赛前请不要用。
- 导入侧按「比赛 + 合同类型 + 名称」判重，名称缺省取合同类型名 —— 所以**一种合同类型通常只预置一份**，
  区分单据请在参与方的合同编号上做。

### 3.8 账号与消息

| 用户名 | 角色 | 显示名 | 公司管理范围 | 查看范围 | 合同查看范围 | 权限键 |
| --- | --- | --- | --- | --- | --- | --- |
| auto_player_a | PLAYER | 玩家A | 西岭锂业; 中原创能; 车都新能源 | 同左 | 同左 | |
| auto_referee | COMPETITION_ADMIN | 本场裁判 | 全部 9 家 | 同左 | 同左 | contract:manage; contract:audit; contract:execute |

- 四套范围**留空 = 该账号登录后什么都看不到**，玩家账号至少给「公司管理范围」。
- 新建账号密码是随机值且强制首次登录改密，需由超管在「账号管理」里重置后交付选手。
- 用户名是**全局**的：同一个用户名导入到第二场比赛时，只会把公司范围并进去，不会改归属比赛。
- 消息表里 `正文` 想换行可以写 `\n`，程序会还原成换行。

## 4. 检查与导入

```powershell
# 只看会建出什么（强烈建议每次改完表都跑一遍，10 秒）
python examples/excel/build_from_sheets.py 我的比赛.xlsx --inspect

# 建比赛 + 预演（事务回滚，一行都不落库）
python examples/excel/build_from_sheets.py 我的比赛.xlsx --create-competition --dry-run

# 建比赛 + 真正导入
python examples/excel/build_from_sheets.py 我的比赛.xlsx --create-competition

# 导入到已有比赛 / 只导某个分组 / 只处理某几张表
python examples/excel/build_from_sheets.py 我的比赛.xlsx --competition 189
python examples/excel/build_from_sheets.py 我的比赛.xlsx --competition 189 --scope company
python examples/excel/build_from_sheets.py 我的比赛.xlsx --competition 189 --sheets 产业类型,公司,公司字段值
```

### 4.1 怎么读 `--inspect` 的输出

1. **比赛名**：确认没写错（新建比赛用它当唯一名）。
2. **已处理的工作表**：逐张核对你这次想建的表都在，且行数对得上（多/少都是信号）。
3. **提示**：引用表缺失、合同类型来自脚本、老写法被归一……都会在这里说清楚。
4. **体检提醒**：不阻断，但值得看 —— 例如：
   - `地图节点孤立`：不可达，运费算不出来；
   - `产业类型缺 location 字段`：地图/运费/区域总览会失效；
   - `区域总览卡片的 industryFieldId 仍是占位值 0`：需要第二遍导入（见下）。
5. **产出资源**：最终会写进比赛的东西，逐类清点。

### 4.2 两遍导入：总览卡片为什么要第二次

`industryFieldId` 是数据库主键，而产业字段是**全局资源**、跨比赛复用。首次导入某个库时字段还不存在，
卡片拿不到 id（只影响卡片取值，不报错）。所以：

```powershell
# 第一遍：把产业字段建出来
python examples/excel/build_from_sheets.py 我的比赛.xlsx --competition 189
# 第二遍：带 --competition 再跑一次（程序会自动回填卡片字段 id），覆盖模式刷新
python examples/excel/build_from_sheets.py 我的比赛.xlsx --competition 189 --mode overwrite --allow-non-empty
```

### 4.3 `append` 与 `overwrite` 的差别

| 模式 | 行为 | 什么时候用 |
| --- | --- | --- |
| `append`（默认） | 只补缺；已存在的记录**原样保留** | 第一次导入、往老比赛补内容 |
| `overwrite` | 已存在的记录**按表格更新**（保留主键与关联） | 改完表想刷新已有数据（改名字、改数值、刷卡片、更新合同类型） |

> 注意：**合同实例**（比赛内的预置合同）即使 `overwrite` 也只会被跳过；要改预置实例的参与方/输入项，
> 先在「合同管理」里删掉它再导入。**合同类型**（全局模板）在 `overwrite` 下可以正常更新。

## 6. 内容隔离与拆表

| 你想要的 | 怎么做 |
| --- | --- |
| 只建公司，其他一律不建 | 工作簿里只放 `产业类型 + 产业字段 + 区域 + 公司 (+公司字段值)`，用 `--scope company` 导入 |
| 同一个工作簿，这次只建一部分 | `--sheets 公司,公司字段值`（引用表要一起带上，否则会报错并提示你） |
| 战术/公司/合同分给不同人维护 | 拆成多个工作簿，各自包含自己那张表 + 它引用的表；`--name` 指定比赛名 |
| 想进 git、想 diff、想批量替换 | 用「一个目录 + 每张表一个 CSV」当输入；`make_template.py --from-sheets 目录 --out x.xlsx` 可转回 xlsx |
| 不想装 Excel | CSV 目录完全等价（Excel 另存为 CSV 或用文本编辑器维护都行） |

`--scope` 的取值就是规范里的「分组」：`competition` / `industry` / `company` / `supply` / `geo` / `tech` / `market` / `access`。

## 7. 常见错误速查

| 屏幕上看到 | 原因 | 怎么改 |
| --- | --- | --- |
| `表头里有规范之外的列：单价；本表可用列：原料名称（name）、…` | 表头拼错或多加了列 | 按提示改表头；列名要写规范里的中文表头 |
| `缺少必填列：原料名称` | 必填列被删了或改了名 | 补回该列（`--spec` 里能查到哪些是必填） |
| `第 5 行的必填列「公司名称」为空` | 该行缺关键内容 | 补内容或删掉这行 |
| `表头重复（中文表头与英文参数名指向同一列…）` | 同一列写了中英两个表头 | 只留一个 |
| `引用的 产业类型（全局）「原料开采」尚未在本构建器中登记；本工作簿里没有「产业类型」表` | 少了引用表 | 把 `产业类型` 表放进来（它很小），或别用 `--sheets` 把它过滤掉 |
| `未知字段「现金x」` | 公司表的额外列名拼错 | 改成字段名称或字段键 |
| `字段名「X」在多个产业下对应不同字段键` | 不同产业里同名字段绑了不同键 | 直接写字段键 |
| `合同类型 … 找不到合同类型 key=…` | `脚本路径` 或 `类型标识` 写错 | 核对脚本路径（相对 backend 目录或表格所在目录）与 key |
| 提示「把 N 处老写法 `{"from": "input"}` 归一成了引擎值源」 | 从旧文档复制了合同 JSON | 无需处理（已自动修正）；新写请直接用 `{"type":"INPUT"}` |
| 提示「把 N 处检查的老写法 `kind="FIELD"` 归一成了 `FIELD_COMPARE"`」 | 同上 | 同上 |
| 合同执行后金额没变 / 恒为 0 | 效果范围形状不对，或输入项没填 | 检查 `{"type":"INPUT"}`；把输入项在「合同实例」表里填全 |
| 检查总是不过 | 检查种类写成 `FIELD`（应为 `FIELD_COMPARE`），或条件本身不满足 | 改种类；核对金额/配额 |
| 卡片没数据 | 卡片字段 id 还是占位 0 | 第二遍导入（`--mode overwrite`） |
| 重复导入后消息变多 | 消息不做判重 | 删除重复消息（`auto_chain_setup.py --finish` 可去重） |
| 账号登录后什么都看不到 | 四套公司范围是空的 | 在 `账号` 表里补「公司管理范围」等 |
| 删除比赛时报 `ProtectedError` | 比赛里有燃料 + 载具（燃料是 PROTECT 外键） | 先删载具、再删燃料、最后删比赛 |

## 8. 进阶技巧

1. **计算字段**：`计算图` 列写 `cash + bank_deposit` 即可；多字段会自动串成嵌套求和。
   需要复杂图（分支、聚合、消费者需求）时，在前端「产业计算图」里搭好，把导出的 JSON 贴进这一格。
   注意：计算字段只在「接口写公司字段」与「财年开始」时重算，合同落账不会触发 —— 需要时跑
   `auto_chain_setup.py --recompute-calc`。
2. **字典 / 列表字段**：字典用于库存台账（`{"原矿": 120}`），列表用于已解锁科技等；
   合同里对字典字段的效果只能写常量键值（要按数量累加就用循环，见合同类型脚本里的写法）。
3. **金额精度**：所有金额、单价按文本写（`0.05`、`600000`），不要写成科学计数法。
4. **合同类型用代码**：复杂合同（地点价、控制流、循环）建议写成脚本（见
   `backend/examples/contracts/auto_chain_contracts.py`），表格里只写脚本路径 —— 两边同源，不会漂移。
5. **多比赛复用**：产业类型/产业字段/合同类型是**全局资源**，第二场比赛导入时会复用；
   想改口径就在表里改完用 `--mode overwrite` 刷新。
