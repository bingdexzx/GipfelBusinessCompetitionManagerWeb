# 比赛 Excel 建包教程（从空表到一场能打的比赛）

> 这份教程带你**从零**用表格文件建出一场比赛的**框架**：填表 → 检查 → 建比赛 → 导入 →
> 再补上参赛主体（公司 / 账号 / 合同）→ 验收。全程不需要写代码，也不需要装任何东西
> （仓库自带的 Python 环境足够）。
>
> 配套文件：
> - 参考手册（逐表逐列的字段字典）：[比赛 Excel 建包规范](比赛Excel建包规范.md)
> - 空白模板：`backend/examples/excel/比赛建包模板.xlsx`
> - 汽车产业链完整框架示例：`backend/examples/excel/汽车产业链示例.xlsx`
> - 最小框架示例（本教程第 1 节）：`backend/examples/excel/最小示例.xlsx`

---

## 0. 先搞清楚四件事

1. **表格只负责「比赛框架」**：比赛本身、财年、**股票市场规则（股票参数）**、
   行业口径（产业类型 / 产业字段）、区域、地图与物流、物资与产能（原料 / 零件 / 产品 / 科技 / 载具…）、
   消费者需求、合同类型。这些是「换一场比赛仍然成立」的东西。
2. **运行期数据不进表格**：公司、公司字段初始值、账号、区域总览卡片、比赛内的合同实例、消息，
   以及**个股 / 资金账户 / 持仓 / 委托 / K 线** —— 它们绑定具体公司、具体人、具体主键或只在运行时产生，
   请在**界面**维护（第 4 节会走一遍），或者用代码建包脚本一次建齐。
3. **一张工作表 = 一类内容**，表与表之间相互隔离：你想建什么就放哪张表，
   没放的表完全不参与产出。工作簿里若放了「公司」这类表，程序会提示你「该去哪里维护」。
4. **表里的内容不会直接写库**：程序先把它翻译成「比赛建包库」的调用、产出归档，
   再走既有的导入引擎落库（比赛隔离、追加/覆盖、空比赛保护、预演回滚都照旧）。

### 最小示例里有什么

只有 14 张有数据的表，足够构成一个能玩的小世界：

| 表 | 内容示例 |
| --- | --- |
| 比赛 | `微型测试赛（教程示例）` / `ACTIVE` |
| 财年 | `2026` / `ACTIVE` |
| 产业类型 | `9001 原料开采`、`9002 零件加工` |
| 产业字段 | 每个产业 3 个字段：`所在地 location`(STRING)、`现金 cash`(NUMBER)、`库存 inventory`(DICTIONARY) |
| 区域 | `东区`、`西区` |
| 地图节点 / 地图连线 | `东矿`、`西厂`；`东矿 → 西厂 100 公里 公路` |

| 合同类型 | `mini-sale 简易购销合同`（买方付钱、卖方收钱，现金不足则拒绝）——**由脚本 `examples/contracts/mini_contracts.py` 产出**，表格里只写脚本路径 |

**这里没有公司、没有账号、没有合同实例** —— 那些在第 4 节补。

## 2. 认识工作簿

### 2.1 表的清单

表在文件里的**先后顺序不影响结果**（程序按依赖顺序处理）：

| 分组（`--scope`） | 表 |
| --- | --- |
| competition | 比赛、财年、**股票参数** |
| industry | 产业类型、产业字段 |
| geo | 区域、地图节点类型、路径类型、地图节点、地图连线 |
| supply | 燃料、原料、科技、生产线、基建、仓库、零件、产品、载具 |
| tech | 消费者需求 |
| market | 合同类型 |

### 2.2 填写规则（背下这 6 条就够用）

| 想表达 | 就写 |
| --- | --- |
| 布尔 | `是` / `否`（也认 `TRUE/FALSE`、`1/0`、`y/n`） |
| 列表 | `公路;铁路`（分号、顿号、逗号、换行都行） |
| 配比 / 地点价 | `锂矿石*4; 铝土矿*1`、`白云鄂博矿区:180; 上游集运站:195` |
| 复杂结构 | 以 `{` 或 `[` 开头的单元格按 JSON 解析 |
| 注释 / 空行 | 行首写 `#` 或 `//`；整行空白自动忽略 |
| 表头 | 中文表头（推荐）；英文参数名同样可用，但同一列不要写两遍 |

金额、单价、数量**建议直接写数字文本**（`600000`、`0.35`），程序按文本保精度。
**空单元格 = 不填这个参数**，会用建包库的默认值（例如 `产业字段` 的 `字段类型` 留空 = `NUMBER`）。

## 3. 手把手：建一场汽车产业链的框架

下面每一步都可以在模板 `比赛建包模板.xlsx` 上直接做（模板里每张表都有表头 + 一行示例 + 空行）。
完整成品见 `汽车产业链示例.xlsx`。

### 3.1 比赛 + 财年

| 比赛名称 | 状态 |
| --- | --- |
| 2026 汽车产业链测试赛 | ACTIVE |

| 年份 | 状态 |
| --- | --- |
| 2026 | ACTIVE |

- 比赛名**全局唯一**：`--create-competition` 遇到同名比赛会复用而不是新建。
- 不写「比赛」表也能建包：用 `--name` 指定比赛名即可（做多份分表时有用）。
- 财年从非 ACTIVE 改成 ACTIVE 会触发 `FY_START` 定时器字段——如果产业字段里配了定时器，注意顺序。

### 3.2 产业口径（产业类型 + 产业字段）

先定「有哪些产业」（`编码` 全局唯一，跨比赛复用，不要给不同行业用同一个编码）：

| 编码 | 产业名称 | 说明 |
| --- | --- | --- |
| 2001 | 原料开采 | 汽车产业链上游：锂 / 铝 / 铁矿石与橡胶硅砂开采 |
| 2002 | 零部件加工 | 汽车产业链中游：原材料加工合成零部件 |
| 2003 | 整车进销 | 汽车产业链下游：零部件合成整车并进销 |

再给每个产业配字段（**这是全场最需要想清楚的一张表**，合同、卡片、图表都按 `字段键` 绑定）：

| 所属产业 | 字段名称 | 字段键 | 字段类型 | 默认值 | 是否计算字段 | 计算图 | 类型配置 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 2001 | 所在地 | location | STRING | | | | |
| 2001 | 现金 | cash | NUMBER | 0 | | | |
| 2001 | 库存台账 | inventory | DICTIONARY | {} | | | NUMBER |
| 2001 | 货币资金 | total_cash | NUMBER | | 是 | cash + bank_deposit | |
| … | … | … | … | … | | | |

要点：

1. **每个产业都要有一个 `所在地`（`location`）字段**：地图、运费、区域总览都依赖它。
2. `字段键` 用英文（公式里要当变量名用）；`字段名称` 才是给人看的中文。
3. **字典字段**（`DICTIONARY`）用来记库存这类 `{名称: 数量}`，`类型配置` 写 `NUMBER` 表示值是数字。
4. **计算字段**：勾「是」后必须在 `计算图` 里写公式。最常用的是求和，直接写 `cash + bank_deposit`
   （多个字段相加会自动串起来）；复杂图可以直接贴 GGraph JSON。
5. 计算字段与「财年定时器」互斥；定时器字段要同时填 `启用财年定时器=是`、`定时器时机`、`定时器写入值`。

### 3.3 区域

| 区域名称 | 说明 |
| --- | --- |
| 上游资源区 | 锂 / 铝 / 铁矿与橡胶硅砂资源带 |
| 中部智造区 | 动力电池、电驱与轻量化车身产业带 |
| 东部车都 | 整车制造、展销与出口集散地 |

区域是「世界结构」，不是参赛者：公司的归属区域、消费者需求的落地区域都按它填。

### 3.4 地图与物流

| 节点名称 | 节点类型 | 所属区域 | X坐标 | Y坐标 |
| --- | --- | --- | --- | --- |
| 白云鄂博矿区 | 矿区 | 上游资源区 | 140 | 120 |
| 上游集运站 | 物流枢纽 | 上游资源区 | 360 | 300 |
| 中部智造园 | 产业园区 | 中部智造区 | 620 | 300 |

| 起点节点 | 终点节点 | 距离(公里) | 路径类型 |
| --- | --- | --- | --- |
| 白云鄂博矿区 | 上游集运站 | 120 | 公路 |
| 上游集运站 | 中部智造园 | 420 | 铁路 |

- 需要先用「地图节点类型」「路径类型」两张表把这些**类型名**建出来。
- 节点的 `所属区域` 是**文本**（不是外键），区域总览按它把公司/节点归到区域。
- 同一对「起点 + 终点」只能有一条连线；反向是另一条（`A→B` 与 `B→A` 可以同时存在）。
- 孤立节点（没有任何连线）不可达，运输合同算不出路程 —— `--inspect` 的体检提醒会点出来。

### 3.5 物资与产能

依赖方向是固定的：**原料 → 零件 → 产品**（零件配方只能引用原料，产品配方只能引用零件）。

| 表 | 关键列 | 示例 |
| --- | --- | --- |
| 燃料 | 燃料名称 / 每升单价 | `柴油` / `7.6` |
| 原料 | 原料名称 / 产地 / 碳排系数 / 类型 / 地点价 | `锂矿石` / `白云鄂博矿区` / `0.52` / `NORMAL` / `白云鄂博矿区:180; 上游集运站:195` |
| 科技 | 科技名称 / 层级 / 研发费用 / 前置科技 | `整车平台化` / `2` / `200000` / `电池成组技术; 电驱系统集成` |
| 零件 | 零件名称 / 原料配比 / 所需科技 | `动力电池包` / `锂矿石*4; 铝土矿*1` / `电池成组技术` |
| 产品 | 产品名称 / 零件配比 / 所需科技 | `纯电轿车` / `动力电池包*1; 驱动电机*1` / `整车平台化` |
| 生产线 | 生产线名称 / 单价 / 用工人数 / 年产能 | `电芯产线` / `2400000` / `120` / `6000` |
| 基建 | 基建名称 / 占地面积 / 单价 / 启用费用 / 6 项加成 | `光伏电站` / `160` / `1200000` / `50000` / … / `0.12` |
| 仓库 | 仓库名称 / 仓库种类 / 容量 / 单价 | `原料仓` / `MATERIAL` / `30000` / `400000` |
| 载具 | 载具名称 / 燃料 / 可通行路径类型 / 每公里油耗 / 载货量 / 单价 / 碳排系数 | `重型卡车` / `柴油` / `公路` / `0.35` / `30` / `260000` / `0.9` |

- **地点价**是「同一原料在不同节点不同价」的来源；合同里按卖方所在地取价时会用到。
- 载具**必须绑燃料**，并且至少有一条可通行路径类型，否则运输路径校验会失败。
- 仓库四种种类（`MATERIAL/PART/PRODUCT/FUEL`）建议都建，否则对应物资无处存放。

### 3.6 消费者需求

| 区域名称 | 产品名称 | 需求量 | 备注 |
| --- | --- | --- | --- |
| 东部车都 | 纯电轿车 | 1200 | 城市通勤主力车型 |

导入按「区域 + 产品 + 数量」去重 —— **改需求量等于新增一条**，不是修改原记录。

### 3.7 股票参数（市场规则）

股票系统里**只有「规则」进表格**：单轮限幅、单轮最大波动、做市商数量与点差、随机事件、估值回归…
个股与资金账户绑定具体公司/人/主键，留在「股票管理」；持仓、委托、K 线由引擎运行时生成。

**键值两列，每行一个参数；只填要改的，没写的键运行期自动取系统默认**：

| 参数 | 值 |
| --- | --- |
| limitPct | 0.08 |
| maxMovePct | 0.05 |
| mmMinQty | 500 |
| mmMaxQty | 20000 |
| mmSelfTradeEnabled | 否 |
| interventionMode | expand-limit |

常用参数（完整 23 个键见 [规范第 4 节](比赛Excel建包规范.md#4-数值口径与类型对照)）：

| 参数 | 含义 | 系统默认 |
| --- | --- | --- |
| `limitPct` | 单轮涨跌幅上限 | 0.10 |
| `maxMovePct` | 单轮最大波动（须 ≤ `limitPct`） | 0.05 |
| `interventionMode` | 干预模式：`regression` / `expand-limit` | regression |
| `mmMinQty` / `mmMaxQty` | 做市商单笔最小 / 最大数量（须 ≤） | 500 / 50000 |
| `mmSpreadPct` | 做市商点差 | 0.015 |
| `mmSelfTradeEnabled` | 做市商自成交开关 | 是 |
| `mmBadNewsProb` / `mmGoodNewsProb` | 利空 / 利好概率 | 0.03 / 0.02 |

三件必须知道的事：

1. **留空 = 沿用系统默认**：整张表空着（或干脆不放这张表）就完全不产出股票参数，目标比赛保持默认；
2. **导入会直接覆盖**目标比赛的参数（不受 `--mode append/overwrite` 影响）→ 先 `--dry-run` 看结果再真导；
3. **表格只能设定、不能「恢复默认」**：想回到系统默认，用接口 `PATCH /api/competitions/:id {"stockConfig": null}`；
   前端目前也**没有**比赛级股票参数页面（只有「推进轮次」时的临时覆盖），所以这张表是目前配置规则的正规入口。

表格层会帮你挡住：未知参数名（给最相近的名字）、`limitPct < maxMovePct`、`mmMinQty > mmMaxQty`；
`limitPct > 0.10` 会额外提示「玩家更容易拉板」（引擎有防连板兜底，但建议不超过 0.10）。

### 3.8 合同类型（只写脚本路径）

合同类型是**框架**（模板），进表格；比赛内的**合同实例**绑定具体公司，属于运行数据（第 4 节）。

**合同类型一律由代码脚本创建**（「合同类型代码化」建库），表格里只写「脚本路径 + 类型标识」：

| 脚本路径 | 类型标识 | 是否启用 |
| --- | --- | --- |
| examples/contracts/auto_chain_contracts.py | auto-mining | 是 |
| examples/contracts/auto_chain_contracts.py | auto-purchase-sale | 是 |
| examples/contracts/auto_chain_contracts.py | auto-transport | 是 |

- **脚本路径**：必填；相对 `backend` 目录或表格所在目录都行。
- **类型标识**：填了就只引入这一个；**留空则引入该脚本产出的全部合同类型**（一行搞定）。
- **是否启用**：对应合同类型的 enabled 开关。

**为什么不在表格里手写合同 JSON**：参与方 / 输入项 / 效果 / 前置检查这四份 JSON 是引擎的底层格式，
手写极易写错，而引擎对写错的形状往往**静默按 0 计算**（金额恒为 0）或让检查**恒不通过**。
代码建库把这四份 JSON 编译出来，还自带字段类型契约与体检：

```python
# backend/examples/contracts/mini_contracts.py（最小示例引用的脚本，全文十来行）
from apps.contracts.builder import ContractType

def build():
    ct = ContractType("mini-sale", "简易购销合同", description="买方付钱给卖方，现金不足则拒绝")
    seller = ct.party("seller", "卖方")
    buyer = ct.party("buyer", "买方")
    amount = ct.input("amount", "成交金额", "number", required=True, default="1000")

    ct.check(amount > 0, label="金额校验", error="成交金额必须大于 0")
    ct.check(buyer.field("cash") >= amount, label="付款校验", error="买方现金不足以支付货款")

    ct.sub_number(buyer.field("cash"), amount)      # 具名效果：自带字段类型契约
    ct.add_number(seller.field("cash"), amount)
    return ct
```

**写一个新合同类型的工作流**（详细写法见 [合同类型代码化](CONTRACT_TYPE_BY_CODE.md)）：

```powershell
cd backend
# ① 照抄 examples/contracts/mini_contracts.py 写自己的脚本（复杂逻辑见 auto_chain_contracts.py）
# ② 静态体检（纯只读，不写库、不跑引擎）
python manage.py build_contract_types 我的合同.py --competition <比赛id> --check
# ③ 用真实公司试算（事务回滚；能发现「检查不通过」「字段不存在」等问题）
python manage.py build_contract_types 我的合同.py --competition <比赛id> --trial
# ④ 两种落地方式，选一个：
python manage.py build_contract_types 我的合同.py --competition <比赛id> --import   # 直接导入
#    或：把脚本路径写进「合同类型」表，跟着比赛框架一起导入（本教程的方式）
```

三个必须知道的点：

1. 合同类型是**全局模板**：改完脚本用表格再导入时记得加 `--mode overwrite`，
   否则已存在的模板会被保留（`append` 模式只补缺）。
2. **脚本本身会报错就会立刻失败**：路径写错、脚本里抛异常、类型标识写错，表格工具都会给出明确提示
   （类型标识写错时会列出该脚本实际产出哪些 key）。
3. 若脚本里用 `keep_effects()` 保留了从旧文档复制来的 JSON，表格工具仍会自动修正其中
   `{"from":"input"}`（引擎会静默按 0 算）与检查 `kind:"FIELD"`（引擎没有这个种类，检查恒不通过）
   两种老写法并打印提示 —— 但**新写脚本不要照抄这些老写法**。

---

## 4. 补齐运行数据（公司 / 账号 / 卡片 / 合同 / 消息）

框架导完之后，这场比赛还「没人、没钱、没合同」。这一步在**界面**上做最自然：

| 要做的事 | 去哪里 | 要点 |
| --- | --- | --- |
| 建参赛公司 | 「公司管理」→ 新建 | 选所属产业 + 所属区域；`所在地` 填**地图节点名**（运费/地价按它算） |
| 填公司初始字段 | 「公司管理 → 公司详情」 | 现金、库存（JSON，如 `{"原矿": 120}`）、配额等按产业字段逐项填 |
| 建账号并授权 | 「账号管理」 | 角色选 PLAYER/裁判；四套公司范围至少给「公司管理范围」，否则登录后什么都看不到 |
| 交付选手口令 | 「账号管理 → 重置密码」 | 新建账号密码是随机值且强制首登改密 |
| 配置区域总览卡片 | 「区域总览」 | 卡片绑定「公司 + 产业字段」，字段是全局资源、跨比赛复用 |
| 建比赛内的合同 | 「合同管理」→ 新建 | 选合同类型（来自第 3.8 节的脚本）→ 选参与方公司 → **把每个输入项都填上**（引擎不套默认值）→ 保持草稿 |
| 发布开赛公告 | 「消息中心」 | 发给全体或指定账号 |

> 想跳过界面、可复现地一次建齐（也方便做自动化测试），用代码建包脚本：

```powershell
cd backend
# 把「参赛主体 + 合同实例 + 卡片 + 消息」补到已有比赛（框架部分会被识别为已存在而保留）
.\.venv\Scripts\python.exe manage.py build_competition examples/competitions/auto_chain_competition.py `
    --competition <比赛id> --resources companies,companyFieldValues,contractInstances,overviewCards,messages `
    --mode overwrite --allow-non-empty
```

- 该脚本的 9 家公司 / 3 份预置合同与表格示例是同一套内容，两边不会打架。
- 用 `--resources` 只导运行数据，可以避免把示例账号也一起建进你的比赛（账号是全局的）。
- 设 `AUTO_CHAIN_COMPETITION_ID=<比赛id>` 环境变量能让总览卡片的字段 id 自动回填。

## 5. 检查与导入

```powershell
# 只看会建出什么（强烈建议每次改完表都跑一遍，10 秒）
python examples/excel/build_from_sheets.py 我的比赛框架.xlsx --inspect

# 建比赛 + 预演（事务回滚，一行都不落库）
python examples/excel/build_from_sheets.py 我的比赛框架.xlsx --create-competition --dry-run

# 建比赛 + 真正导入
python examples/excel/build_from_sheets.py 我的比赛框架.xlsx --create-competition

# 导入到已有比赛 / 只导某个分组 / 只处理某几张表
python examples/excel/build_from_sheets.py 我的比赛框架.xlsx --competition 189
python examples/excel/build_from_sheets.py 我的比赛框架.xlsx --competition 189 --scope supply
python examples/excel/build_from_sheets.py 我的比赛框架.xlsx --competition 189 --sheets 产业类型,产业字段
```

### 5.1 怎么读 `--inspect` 的输出

1. **比赛名**：确认没写错（新建比赛用它当唯一名）。
2. **已处理的工作表**：逐张核对你这次想建的表都在，且行数对得上（多/少都是信号）。
3. **提示**：引用表缺失、合同类型来自脚本、老写法被归一、放了运行数据的表被跳过……都会在这里说清楚。
4. **体检提醒**：不阻断，但值得看 —— 例如 `地图节点孤立`（不可达，运费算不出来）、
   `产业类型缺 location 字段`（地图/运费/区域总览会失效）。
5. **产出资源**：最终会写进比赛的东西，逐类清点。

### 5.2 `append` 与 `overwrite` 的差别

| 模式 | 行为 | 什么时候用 |
| --- | --- | --- |
| `append`（默认） | 只补缺；已存在的记录**原样保留** | 第一次导入、往老比赛补内容 |
| `overwrite` | 已存在的记录**按表格更新**（保留主键与关联） | 改完表想刷新已有数据（改数值、改配方、刷新合同类型） |

> 运行数据（公司、账号、合同实例、卡片、消息）不跟着框架走：改它们要在界面里改。

## 7. 内容隔离与拆表

| 你想要的 | 怎么做 |
| --- | --- |
| 只建物资链，其他不动 | 工作簿里只放 `产业类型 + 产业字段 + 燃料 + 原料 + 科技 + 零件 + 产品 + 载具`，用 `--scope supply` 导入 |
| 同一个工作簿，这次只建一部分 | `--sheets 原料,零件,产品`（引用表要一起带上，否则会报错并提示你） |
| 产业/地图/物资分给不同人维护 | 拆成多个工作簿，各自包含自己那张表 + 它引用的表；`--name` 指定比赛名 |
| 想进 git、想 diff、想批量替换 | 用「一个目录 + 每张表一个 CSV」当输入；`make_template.py --from-sheets 目录 --out x.xlsx` 可转回 xlsx |
| 不想装 Excel | CSV 目录完全等价（Excel 另存为 CSV 或用文本编辑器维护都行） |

`--scope` 的取值就是规范里的「分组」：`competition` / `industry` / `geo` / `supply` / `tech` / `market`。

## 8. 常见错误速查

| 屏幕上看到 | 原因 | 怎么改 |
| --- | --- | --- |
| `表头里有规范之外的列：单价；本表可用列：原料名称（name）、…` | 表头拼错或多加了列 | 按提示改表头；列名要写规范里的中文表头 |
| `缺少必填列：原料名称` | 必填列被删了或改了名 | 补回该列（`--spec` 里能查到哪些是必填） |
| `第 5 行的必填列「原料名称」为空` | 该行缺关键内容 | 补内容或删掉这行 |
| `表头重复（中文表头与英文参数名指向同一列…）` | 同一列写了中英两个表头 | 只留一个 |
| `引用的 产业类型（全局）「原料开采」尚未在本构建器中登记；本工作簿里没有「产业类型」表` | 少了引用表 | 把 `产业类型` 表放进来（它很小），或别用 `--sheets` 把它过滤掉 |
| `工作表「公司」不属于表格规范的「比赛框架」，已跳过：… 请在「公司管理」界面维护` | 把运行数据放进了表格 | 这是正常提示：按它去界面维护（第 4 节） |
| `工作表「股票」/「资金账户」… 请在「股票管理」维护` | 把个股或资金账户放进了表格 | 同样正常：它们绑定公司/人/字段主键，去「股票管理」建 |
| `未知的股票参数「limittPct」；是不是想写：limitPct…` | 股票参数键名拼错 | 按提示改成正确键名（可用键会全部列出） |
| `limitPct（单轮限幅 0.05）不能小于 maxMovePct（0.08）` | 两个参数填反了 | 保证 `limitPct ≥ maxMovePct`；同理 `mmMinQty ≤ mmMaxQty` |
| `第 2 行的必填列「脚本路径」为空` | 合同类型表漏了脚本路径 | 合同类型必须来自代码脚本，见第 3.8 节 |
| `脚本 … 里没有合同类型「xxx」；该脚本产出：…` | `类型标识` 写错 | 按提示改成脚本里真实的 key，或把该格留空（引入全部） |
| `合同类型脚本不存在：…` / `执行失败：…` | 脚本路径写错，或脚本自身报错 | 核对路径（相对 backend 或表格目录）；先单独跑 `python manage.py build_contract_types <脚本> --check` 排错 |
| 提示「把 N 处老写法 `{"from": "input"}` 归一成了引擎值源」/「`kind="FIELD"` 归一成了 `FIELD_COMPARE`」 | 脚本里 `keep_effects()` 保留了旧文档的 JSON | 无需处理（已自动修正）；新写脚本请用 `{"type":"INPUT"}` 与 `FIELD_COMPARE` |
| 合同执行后金额没变 / 恒为 0 | 效果取值范围不对，或输入项没填 | 用代码建库的具名效果（`ct.sub_number(...)` 等）；在「合同管理」里把输入项填全 |
| 检查总是不过 | 检查种类写成 `FIELD`（应为 `FIELD_COMPARE`），或条件本身不满足 | 用 `ct.check(buyer.field("cash") >= amount)` 这类比较表达式；核对金额/配额 |
| 改了表格再导入却没生效 | 默认是 `append`（已存在的保留） | 加 `--mode overwrite`（合同类型、原料、配方等都会被刷新） |
| 卡片没数据 | 卡片绑定的字段主键不对 | 在「区域总览」里重新选字段（字段是全局资源，跨比赛复用） |
| 账号登录后什么都看不到 | 四套公司范围是空的 | 在「账号管理」里给该账号配「公司管理范围」等 |
| 删除比赛时报 `ProtectedError` | 比赛里有燃料 + 载具（燃料是 PROTECT 外键） | 先删载具、再删燃料、最后删比赛 |

## 9. 进阶技巧

1. **计算字段**：`计算图` 列写 `cash + bank_deposit` 即可；多字段会自动串成嵌套求和。
   需要复杂图（分支、聚合、消费者需求）时，在前端「产业计算图」里搭好，把导出的 JSON 贴进这一格。
   注意：计算字段只在「接口写公司字段」与「财年开始」时重算，合同落账不会触发 —— 需要时跑
   `auto_chain_setup.py --recompute-calc`。
2. **字典 / 列表字段**：字典用于库存台账（`{"原矿": 120}`），列表用于已解锁科技等；
   合同里对字典字段的效果只能写常量键值（要按数量累加就用循环，见合同类型脚本里的写法）。
3. **金额精度**：所有金额、单价按文本写（`0.05`、`600000`），不要写成科学计数法。
4. **合同类型用代码**：所有合同类型都由脚本创建（第 3.8 节）——
   简单合同照抄 `backend/examples/contracts/mini_contracts.py`，
   带地点价 / 控制流 / 循环的复杂合同看 `auto_chain_contracts.py`；
   完整写法与体检说明见 [合同类型代码化](CONTRACT_TYPE_BY_CODE.md)。
   表格里只写脚本路径，两边同源，不会漂移。
5. **多比赛复用**：产业类型 / 产业字段 / 合同类型是**全局资源**，第二场比赛导入时会复用；
   想改口径就在表里改完用 `--mode overwrite` 刷新。
6. **一次建齐（框架 + 主体）**：`examples/competitions/auto_chain_competition.py` 是代码建包，
   覆盖框架与参赛主体；与表格框架可以混用（框架部分会被识别为已存在而保留）。
